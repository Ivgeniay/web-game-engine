# Этап 12. Расширенные поля

Прочитай `CLAUDE.md` и в `docs/ui-catalog.md` раздел «Этап 12», записи Slider, TextArea, FlagsField, SplitButton, ColorPicker, ColorField, ListEditor, RectField, BoundsField и общие правила полей ввода. Все правила `CLAUDE.md` действуют на этом этапе, включая протокол изменения значения, стек отмены и документацию на двух языках.

Требования к поведению берутся из каталога. Ниже — решения по развилкам.

## Цель

После этого этапа инспектор умеет показывать почти любой тип свойства: диапазон, многострочный текст, набор флагов, цвет, массив значений, прямоугольник и границы. В демо-сцене эти поля появляются у компонентов.

## Порядок работы

Проектный 12.1 — короткий, только по развилкам, которые не решены ниже. Дальше подшаги, каждый — один логический модуль:

- 12.2 — Slider и TextArea;
- 12.3 — FlagsField и SplitButton;
- 12.4 — ColorPicker и ColorField;
- 12.5 — ListEditor, RectField и BoundsField;
- 12.6 — демо-сцена, документация и итог.

После каждого подшага остановись, перечисли созданные и изменённые файлы и жди подтверждения. Мелкие находки — в `docs/backlog.md` без остановки, явные ошибки в тексте документации исправляй сразу.

## Разрешённые зависимости

Новых пакетов нет.

## Решения, принятые заранее

### Общее

- Все поля следуют протоколу `preview`, `commit`, `cancel`: одно перетаскивание ползунка, одна сессия выбора цвета, одна операция над списком — одна запись отмены.
- Страницы витрины сразу на двух языках, по правилам раздела «Витрина».

### Slider

- Поле ввода числа справа, как в Unity, на NumberField.
- Логарифмическая шкала — опция.
- Вариант NumberField с полосой диапазона внутри (как в Godot) — не на этом этапе.

### FlagsField

- На основе Select и пунктов-флажков Menu. Список не закрывается при переключении флага.
- Пункты «Ничего» и «Всё», сводная подпись поля («Смешано», список имён, «Ничего», «Всё»). Все подписи передаёт потребитель.

### Цвет

- Тип цвета каркаса: каналы `r`, `g`, `b`, `a` от 0 до 1, как в Unity. Интеграция переводит его в свой формат.
- ColorPicker: квадрат насыщенности и яркости, полоса тона, полоса прозрачности, числовые поля RGB и HSV, поле HEX. Перетаскивание — предпросмотр, закрытие Popover — одна фиксация, Esc отменяет весь выбор.
- Пипетка через `EyeDropper API`, только где он есть; где нет — кнопки пипетки нет.
- HDR-цвета (значения больше 1) и сохранённые образцы — не на этом этапе.
- Шахматка под прозрачным образцом — из токенов. Если для неё нужны новые цветовые токены, добавь их в обе темы и в тест тем.
- Цвет образца — инлайн-стилем: это данные, а не оформление.

### ListEditor

- Добавление, удаление и перестановка элементов, отрисовка элемента — функцией потребителя.
- Перестановка мышью — механизмом переноса этапа 10, с клавиатуры — Alt+стрелки на ручке.
- Каждая операция — одна запись отмены.

### RectField и BoundsField

- Составные поля на VectorField, по каталогу.

## Демо-сцена

- Light: цвет через ColorField, интенсивность через Slider.
- Rigidbody: ограничения через FlagsField (заморозка позиции и поворота по осям).
- Новый компонент с массивом, например точки маршрута — список векторов через ListEditor.
- Новый компонент с многострочным текстом, например заметка к объекту, — через TextArea.
- Все изменения отменяются, при множественном выделении работают смешанные значения там, где поле их поддерживает.

## Критерии приёмки

- Все элементы этапа 12 из каталога есть, у каждого тесты и страница в разделе Components на двух языках.
- Выбор цвета, перетаскивание ползунка и операции со списком дают по одной записи отмены.
- В демо-сцене новые поля работают у компонентов, изменения отменяются.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят без ошибок и предупреждений, полный прогон после последней правки.

## Что не входит в этап

- GradientField, CurveField, MinMaxSlider: этапы later.
- HDR-цвета, сохранённые образцы, выражения в числовых полях.
- Механизм, который строит инспектор по описанию свойств: этап 13.
