# Этап 2. Витрина-документация

Прочитай `CLAUDE.md` в корне репозитория. Все его правила действуют на этом этапе. При противоречии главнее `CLAUDE.md`.

## Контекст

Проект — открытый каркас редактора, который разработчики движков берут исходным кодом. Витрина (`showcase.html`) становится его живой документацией: для каждого UI-компонента и механизма каркаса там есть страница с описанием, живым примером и кодом примера. Разработчик открывает страницу, видит компонент в работе, читает, как им пользоваться, и копирует пример. Заодно витрина — место ручного тестирования UI.

Витрина доступна только в `pnpm dev` и не попадает в сборку. Это не меняется.

## Цель

Превратить витрину из одной длинной страницы в документацию: навигация по страницам, единый шаблон страницы, примеры, у которых живое демо и показанный код — один и тот же файл. Перенести в новую структуру всё, что уже есть на витрине.

## Порядок работы

Этап разбит на подшаги. Каждый подшаг — один логический модуль. После каждого подшага остановись, перечисли все созданные и изменённые файлы, кратко опиши решения и жди подтверждения.

## Разрешённые зависимости

Новых пакетов нет: ни роутера, ни подсветки синтаксиса, ни генераторов документации.

## Требования

### Язык

Все тексты документации на английском. Система локализации на витрину не распространяется: документация — не интерфейс редактора.

### Навигация

- Слева боковое меню: разделы и страницы внутри них. Справа содержимое текущей страницы.
- Адрес страницы хранится в хэше URL, например `showcase.html#/foundations/colors`. Ссылку на страницу можно скопировать, после перезагрузки открывается та же страница, кнопки «назад» и «вперёд» браузера работают.
- Неизвестный адрес открывает обзорную страницу.
- Переключатель темы — в шапке витрины, общий для всех страниц.
- Список страниц — единый реестр: идентификатор, раздел, название, компонент страницы. Добавить страницу — значит добавить одну запись в реестр, навигация строится из него.

### Шаблон страницы

Каждая страница строится из общих частей:

- название и короткое описание: что это и когда этим пользоваться;
- разделы страницы с заголовками;
- блок примера: живое демо, под ним код примера и кнопка копирования кода.

### Примеры

- Пример — отдельный файл-компонент. Витрина отображает его вживую и показывает его исходный текст, загруженный через `?raw`. Демо и показанный код — один и тот же файл, поэтому разойтись не могут.
- Пример написан так, как его написал бы разработчик движка: импорты через `@/` из каркаса, никаких внутренностей витрины. Его можно скопировать в свой код и он заработает.
- Пример короткий и показывает одну мысль. Несколько вариантов использования — несколько примеров.
- В примерах, как и везде, нет комментариев. Все пояснения — в тексте страницы рядом с примером.

### Оформление

- Витрина оформлена только токенами каркаса.
- Размеры, нужные только витрине (например, ширина бокового меню), задаются локальными CSS-переменными витрины, объявленными в одном месте. Это не токены каркаса.
- Код примеров — моноширинным шрифтом из токенов, без подсветки синтаксиса.

## Разделы и страницы

Стартовый набор, перенос того, что уже есть на витрине:

- **Overview** — одна страница: что такое каркас, как устроена витрина, как читать страницы.
- **Foundations**:
  - **Themes** — режимы темы, как получить и сменить тему из кода, как писать стили на токенах в CSS Modules. С примерами.
  - **Colors** — все цветовые токены.
  - **Typography** — шрифтовые токены.
  - **Spacing** — шкала отступов.
  - **Sizes** — размеры контролов, панелей, иконок, границ, полосы прокрутки.
  - **Radius and shadows** — радиусы и тени.
  - **Layers and motion** — z-index, длительности, кривые анимации.
  - **Contrast** — таблица пар контраста для текущей темы.

Существующие компоненты витрины (`TokenSection`, `ContrastSection`, `ThemeSwitcher` и хуки) переиспользуются, а не переписываются. Если для этого их нужно изменить, опиши изменения в отчёте.

## Подшаги

### 2.1. Проект, без кода

Пришли предложение и жди решения:

- структура папок `src/showcase/`: где реестр, страницы, примеры, общие части шаблона;
- как устроены реестр страниц и маршрутизация по хэшу;
- соглашение об именах и расположении файлов примеров;
- как страница подключает пример и его исходный текст;
- список файлов по подшагам 2.2–2.4.

### 2.2. Каркас витрины

Реестр страниц, маршрутизация по хэшу, общий макет (шапка с переключателем темы, боковое меню, область страницы), общие части шаблона страницы и блок примера с кодом и копированием. Тесты для логики маршрутизации и реестра: разбор адреса, неизвестный адрес, уникальность идентификаторов страниц.

### 2.3. Перенос содержимого

Страницы Overview и Foundations из списка выше. Страница Themes с примерами: получение текущей темы, смена режима, компонент со стилями на токенах.

### 2.4. Правила

- В `CLAUDE.md` новый раздел «Витрина» с правилами:
  - UI-компонент или механизм каркаса считается готовым, только когда у него есть страница на витрине с описанием, живым примером и кодом примера;
  - пример — отдельный файл, который витрина и показывает вживую, и отображает исходным текстом;
  - пример пишется так, как его написал бы разработчик движка;
  - тексты документации на английском;
  - как добавить страницу.
- В `docs/backlog.md` в «Сделать, когда понадобится»: подсветка синтаксиса в коде примеров; таблица свойств компонента; страницы витрины для компонентов интеграции из `src/engine/`.
- Итоговый отчёт этапа.

## Что не входит в этап

- Новые UI-компоненты каркаса.
- Локализация (следующий этап).
- Публикация витрины отдельным сайтом.

## Критерии приёмки

- Все страницы из списка открываются из бокового меню, адрес страницы сохраняется после перезагрузки, «назад» и «вперёд» работают.
- Неизвестный адрес открывает Overview.
- Всё, что было на прежней витрине, есть в новой структуре.
- У каждого примера живое демо и показанный код — один файл.
- Код примера копируется кнопкой.
- `pnpm build` по-прежнему не включает витрину.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят без ошибок и предупреждений.
