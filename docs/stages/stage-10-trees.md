# Этап 10. Списки, деревья и секции

Прочитай `CLAUDE.md` и в `docs/ui-catalog.md` раздел «Этап 10», записи ListView, TreeView, Foldout, ComponentHeader и общие механизмы «Перетаскивание», «Виртуализация списков», «Управление фокусом». Все правила `CLAUDE.md` действуют на этом этапе. При противоречии главнее `CLAUDE.md`.

Требования к поведению берутся из каталога. Ниже — решения по развилкам и то, что каталог не покрывает.

## Цель

Список и дерево, быстрые на тысячах строк, с выделением, клавиатурой, переименованием, поиском и перетаскиванием. Сворачиваемые секции и заголовок компонента. В демо-сцене Hierarchy и Project показывают деревья, выделение в Hierarchy управляет Inspector, у компонентов в Inspector появляются заголовки.

## Порядок работы

Проектный подшаг 10.1 — короткий, только по развилкам, которые не решены ниже. Дальше подшаги по разбивке раздела «Этап 10» каталога, каждый — один логический модуль. Обновление демо-сцены и документация — в последнем подшаге; если не помещается, допустим один дополнительный подшаг. После каждого подшага остановись, перечисли созданные и изменённые файлы и жди подтверждения.

Мелкие находки, которые не мешают шагу, записывай в `docs/backlog.md` и не останавливайся на них.

## Разрешённые зависимости

Новых пакетов нет.

## Решения, принятые заранее

### Виртуализация

- Свой модуль для строк фиксированной высоты, высота строки — токен. Рисуются только видимые строки с небольшим запасом сверху и снизу.
- Список и дерево остаются быстрыми на 10 000 строк: на витрине есть пример такого размера.

### Данные и состояние

- Данные — плоская модель с идентификаторами, дерево не копируется в компонент. Потребитель даёт функции получения детей и признак «есть ли дети».
- Выделение, развёрнутые узлы и фокусная строка — управляемое состояние, как значения у остальных примитивов.
- Отрисовка строки — функцией потребителя. Иконка и подпись — стандартный вариант строки, который потребитель может заменить.
- Ленивая загрузка потомков — не на этом этапе, пункт в бэклог.

### Выделение

- Одиночное и множественное по каталогу: Shift — диапазон, Ctrl или ⌘ — добавить или убрать, Mod+A — всё.
- Клик по пустому месту списка снимает выделение.
- Выделение неактивного окна рисуется токеном `bg-selection-inactive` — это пара уже проверена тестом контраста.

### Переименование

- F2 на Windows и Linux, Enter на macOS — по каталогу. Двойной клик по подписи тоже начинает переименование.
- Поле переименования — TextField с протоколом этапа 9: Enter фиксирует, Esc отменяет, потеря фокуса фиксирует.

### Поиск

- Фильтр по строке показывает совпадения вместе с предками, предки развёрнуты, совпадение в подписи выделено.
- SearchField над деревом: стрелка вниз из поля переводит фокус в дерево. Пункт бэклога из этапа 9 закрывается.

### Перетаскивание

- Свой механизм переноса данных на Pointer Events по каталогу, с типизированными данными переноса (тип и идентификаторы). Не HTML5 Drag and Drop: тот остаётся только для файлов из ОС и для вкладок dockview.
- В дереве: места вставки «до», «после», «внутрь» с подсветкой, автопрокрутка у краёв, автораскрытие узла при задержке над ним. Нельзя бросить узел внутрь самого себя или своего потомка.
- Перетаскивание с клавиатуры — не на этом этапе, пункт в бэклог.
- Перенос между окнами (например, ассет из Project в Inspector) механизм поддерживает, но в демо не обязателен.

### Foldout и ComponentHeader

- По каталогу. Alt+клик разворачивает и сворачивает вложенные секции.
- Состояние развёрнутости — управляемое; хранит его владелец.

## Демо-сцена

- Объекты сцены получают иерархию (родитель и дети). Hierarchy показывает её деревом.
- Выделение в Hierarchy управляет Inspector; Select выбора объекта в Inspector убирается.
- При выделении нескольких объектов Inspector показывает общие компоненты со смешанными значениями. Изменение применяется ко всем выделенным одной записью отмены.
- Контекстное меню Hierarchy работает с выделением: переименовать, дублировать, удалить. Переименование и перетаскивание (смена родителя и порядка) отменяются через стек.
- Компоненты в Inspector — с ComponentHeader: сворачивание, флажок включения у Rigidbody и Light, меню компонента.
- Project — дерево папок и файлов демо-проекта с поиском. Иконки папок и файлов — из набора каркаса.

## Критерии приёмки

- Все элементы этапа 10 из каталога есть, у каждого тесты и страница в разделе Components.
- Дерево на 10 000 строк прокручивается и разворачивается без задержек.
- Выделение, клавиатура, переименование, поиск и перетаскивание в дереве работают по каталогу.
- В демо-сцене выделение в Hierarchy управляет Inspector, множественное выделение даёт смешанные значения, перетаскивание и переименование отменяются.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят без ошибок и предупреждений, полный прогон после последней правки.

## Что не входит в этап

- Ленивая загрузка потомков, перетаскивание с клавиатуры.
- Таблицы с колонками, сетка значков, двухпанельный Project: этапы next.
- Индикаторы (Spinner, ProgressBar, EmptyState): этап 11.
