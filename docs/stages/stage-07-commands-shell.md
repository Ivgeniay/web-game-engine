# Этап 7. Команды и точки расширения оболочки

Прочитай `CLAUDE.md` в корне репозитория и в `docs/ui-catalog.md` записи MenuBar, ContextMenu, MainToolbar, StatusBar, ConfirmDialog, а также раздел «Общие механизмы» (горячие клавиши, управление фокусом). Все правила `CLAUDE.md` действуют на этом этапе. При противоречии главнее `CLAUDE.md`.

## Контекст

Внешний вид главного меню, тулбара и строки состояния — это сборка уже готовых примитивов. Суть этапа в другом: в механизмах, через которые разработчик движка добавляет свои команды, пункты меню, кнопки и элементы строки состояния, не правя файлы каркаса. Без них единственный способ расширить оболочку — дописывать JSX в файлы каркаса, а это даёт конфликты при каждом обновлении каркаса через git.

Каркас не решает, что лежит в меню и на тулбаре. Он даёт механизмы. Наполнение — дело интеграции. На этом этапе наполнение есть только в демонстрационных примерах витрины.

## Цель

- Реестр команд: действие, подпись, иконка, сочетание клавиш, доступность, отметка.
- Горячие клавиши с контекстами.
- Реестры главного меню, контекстных меню, тулбара и строки состояния.
- Тонкие компоненты MenuBar, MainToolbar, StatusBar, которые рисуют содержимое реестров примитивами этапов 5 и 6.
- ConfirmDialog, который вызывается из кода и возвращает ответ.
- Каркас страницы редактора: сверху меню и тулбар, снизу строка состояния, между ними пустая рабочая область, куда на этапе 8 встанет докинг.

Пять подшагов, каждый — один логический модуль. Больше подшагов не добавляй. После каждого подшага остановись, перечисли все созданные и изменённые файлы, кратко опиши решения и жди подтверждения.

Новых пакетов нет.

## Требования

### Без глобальных экземпляров

Реестры создаются фабриками в точке входа и передаются через провайдер контекста, как сторы темы и языка. В модулях нет глобальных реестров. Тесты и примеры витрины создают свои изолированные реестры.

### Как интеграция подключается

Нужна одна понятная точка, через которую интеграция получает доступ ко всем реестрам каркаса и регистрирует свои элементы при старте. Регистрация возвращает функцию отмены регистрации. Кроме регистрации при старте, нужна регистрация на время жизни компонента: например, окно добавляет свои команды, пока оно открыто. Как это устроено — предложи в 7.1. Папки `src/engine/` ещё нет, она появится на этапе 8, но API должен быть готов к ней.

### Команды

- Команда: идентификатор, подпись `MessageRef`, необязательные иконка и сочетание по умолчанию, действие, условие доступности, необязательное условие отметки (для пунктов-флажков).
- Доступность и отметка вычисляются в момент показа: при открытии меню, при отрисовке кнопки тулбара. Пункт меню и кнопка тулбара одной команды гаснут и загораются одновременно.
- Действие получает контекст вызова: откуда вызвано (меню, тулбар, горячая клавиша, контекстное меню) и данные цели для контекстного меню.
- Дубль идентификатора команды — ошибка в режиме разработки.

### Горячие клавиши

Требования раздела «Горячие клавиши» в каталоге, плюс:

- `Mod` — Ctrl на Windows и Linux, ⌘ на macOS. Строку для Kbd под платформу формирует механизм горячих клавиш.
- Сравнение по физической клавише (`KeyboardEvent.code`), чтобы сочетания работали в русской раскладке. В тестах это проверяется.
- Контексты: глобальный и именованные области, которые задаёт разметка (например, будущее окно Hierarchy). Сочетание из более узкой области имеет приоритет над глобальным.
- Пока фокус в поле ввода, сочетания без модификаторов не срабатывают, с модификаторами — только явно разрешённые для полей.
- Пока открыт Dialog, глобальные сочетания не срабатывают.
- Конфликт: одно сочетание у двух команд в одном контексте — ошибка в режиме разработки.
- Список сочетаний, которые браузер не отдаёт странице, хранится в коде, а сочетание по умолчанию из этого списка — ошибка. Список и проверка покрываются тестом.
- Переназначение сочетаний пользователем — не на этом этапе, но формат должен это допускать.

### Главное меню

- Пункты регистрируются по пути, как в Unity: верхнее меню, подменю, пункт. Порядок внутри уровня — по числовому приоритету, разделители — по группам. Предложи формат в 7.1.
- Каркас задаёт только механизм. Стандартный порядок верхних меню и их подписи задаёт тот, кто регистрирует. Пустые меню не показываются.
- MenuBar по каталогу: F10 переводит фокус в меню; стрелки влево и вправо переходят к соседнему меню; когда одно меню открыто, наведение на соседнее открывает его. Используется управляемый режим Menu и обработчик `onNavigateOut` из этапа 6. Будет ли Alt открывать меню на Windows и Linux, с учётом поведения браузеров, — предложи в 7.1.
- Подписи пунктов меняются при смене языка без перезагрузки.

### Контекстные меню

- Контекстное меню собирается из реестра по идентификатору контекста (например, `hierarchy.item`) и данным цели.
- Интеграция добавляет пункты в любой контекст, в том числе в контексты каркаса.
- Открывается по правому клику, Shift+F10 и клавише контекстного меню. Родное меню браузера подавляется внутри редактора, кроме полей ввода.

### Тулбар и строка состояния

- Зоны тулбара: слева, по центру, справа. Зоны строки состояния: слева и справа. Порядок внутри зоны по приоритету.
- Элемент тулбара — команда (кнопка или переключатель) или произвольный компонент, который регистрирует интеграция (например, Select разрешения окна Game). Элемент строки состояния — произвольный компонент.
- Пункт бэклога «Отключённые элементы в тулбаре» решается на этом этапе.

### ConfirmDialog

- Вызов из кода возвращает `Promise` с ответом.
- Тексты — `MessageRef`.
- Фокус по умолчанию на безопасном действии для разрушительных операций.
- Очередь: второй диалог ждёт закрытия первого.
- «Больше не спрашивать» — не на этом этапе.

### Каркас страницы редактора

- `src/app/App.tsx` показывает каркас: MenuBar, MainToolbar, пустая рабочая область, StatusBar. Размеры по токенам `--size-menubar-height`, `--size-toolbar-height`, `--size-statusbar-height`.
- Каркас сам ничего не регистрирует, поэтому в редакторе меню и тулбар пока пусты. Это нормально: содержимое придёт с интеграцией на этапе 8.
- Строки, которые показывает сам каркас (если появятся), идут через словарь каркаса.

### Витрина

- Страницы механизмов: Commands, Hotkeys, Menu bar, Context menu, Toolbar и status bar, Confirm dialog.
- Каждый пример создаёт собственные изолированные реестры и показывает, как интеграция регистрирует свои элементы. Примеры пишутся так, как их написал бы разработчик движка.
- Страница Hotkeys показывает, как сочетание выглядит на macOS и на Windows.

## Что не входит в этап

- Докинг и окна, папка `src/engine/`: этап 8.
- Стек отмены: этап 9.
- Переназначение сочетаний пользователем, окно горячих клавиш, палитра команд: этапы next и later.
- Конкретное наполнение меню и тулбара.

## Критерии приёмки

- Интеграция может добавить команду, пункт главного меню, пункт контекстного меню, кнопку тулбара и элемент строки состояния, не правя ни одного файла каркаса. Это показано примерами на витрине.
- Пункт меню и кнопка одной команды гаснут одновременно, когда команда недоступна.
- Сочетания работают в русской раскладке, не срабатывают при вводе текста и под Dialog.
- Конфликт сочетаний, дубль команды и запрещённое браузером сочетание — ошибки в режиме разработки, покрытые тестами.
- Подписи меню и тулбара меняются при смене языка без перезагрузки.
- Редактор (`index.html`) показывает каркас страницы.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят без ошибок и предупреждений, полный прогон после последней правки.
