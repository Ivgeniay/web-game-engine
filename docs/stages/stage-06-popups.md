# Этап 6. Всплывающие элементы

Прочитай `CLAUDE.md` в корне репозитория и записи этапа 6 в `docs/ui-catalog.md`: Tooltip, Menu, Select, Popover, Dialog, а также раздел «Общие механизмы» (позиционирование, управление фокусом). Все правила `CLAUDE.md` действуют на этом этапе. При противоречии главнее `CLAUDE.md`. Описания элементов в каталоге — основа требований к поведению и клавиатуре; ниже только то, что каталог не покрывает или что решено дополнительно.

## Цель

Общий слой всплывающих элементов на Floating UI и пять примитивов поверх него: подсказка, меню с подменю, выпадающий список, всплывающая панель и модальный диалог. Временные подсказки через атрибут `title` заменяются настоящим Tooltip.

## Порядок работы

Пять подшагов, каждый — один логический модуль. Больше подшагов не добавляй. После каждого подшага остановись, перечисли все созданные и изменённые файлы, кратко опиши решения и жди подтверждения.

## Разрешённые зависимости

- `@floating-ui/react`, последняя стабильная версия, точная.

Больше ничего. Если понадобится ещё пакет, остановись и спроси.

## Общие требования

- Примитивы этапа не знают о сторах, локализации и реестрах. Все тексты приходят готовыми строками через пропсы.
- Все всплывающие элементы отрисовываются в общий слой в корне документа (портал), чтобы их не обрезали родители с `overflow: hidden` и не перекрывали панели. Слой наследует тему: CSS-переменные тем должны действовать внутри него.
- Z-index только из токенов: `--z-dropdown` для Menu, Select и Popover, `--z-tooltip` для Tooltip, `--z-modal` для Dialog. Всплывающий элемент внутри Dialog (Select в диалоге, подсказка на кнопке диалога) должен оказаться поверх диалога. Проверь это примером на витрине.
- Оформление: фон `bg-popup`, тени `--shadow-popup` и `--shadow-tooltip`, граница и радиус из токенов. Выбор токенов границы опиши в 6.1.
- Вложенность: подменю в Menu, Select или Menu внутри Popover, Popover внутри Dialog. Клик внутри дочернего элемента не закрывает родителя, Esc закрывает только верхний уровень.
- Возврат фокуса: после закрытия любого элемента, который забирал фокус, фокус возвращается туда, откуда его открыли.
- Анимации появления — по желанию, только на токенах длительности и с учётом `prefers-reduced-motion`. Если анимации нет, это не ошибка.
- Триггеры (кнопки, которые открывают всплывающие элементы) — существующие примитивы этапа 5. Если для подключения Floating UI их нужно поправить, опиши правку в 6.1.
- Элемент, открытый внутри Toolbar, не ломает роуминговый фокус тулбара.
- Тесты компонентов: открытие, закрытие всеми способами из каталога, клавиатура, возврат фокуса, атрибуты доступности. Геометрию позиционирования jsdom не считает, её проверяю я на витрине. Для нетривиальной логики — проверка, что тест ловит поломку.
- У каждого элемента страница в разделе Components с описанием, примерами и кодом. У слоя всплывающих элементов — страница механизма, если у него есть что-то, чем пользуется разработчик напрямую.

## Решения, принятые заранее

### Tooltip

- Заменяет атрибут `title` у IconButton и у обрезанного текста Label. Пункт бэклога «Подсказка IconButton через title» закрывается.
- Содержимое: строка и необязательное сочетание клавиш, которое показывается через Kbd.
- Задержки показа и мгновенный показ соседних подсказок по каталогу. Где хранятся значения задержек — в токенах или в константах TS — предложи в 6.1. Это значения поведения, а не оформления.

### Menu

- Пункты описываются данными, а не разметкой: массив пунктов с типами из каталога (действие, флажок, радио, подменю, разделитель, заголовок секции). Это нужно этапу 7, где меню строятся из реестров. Если видишь причину делать иначе, обоснуй в 6.1.
- У пункта: подпись, необязательная иконка, необязательная строка сочетания клавиш, отключённость, обработчик выбора.
- Якорь — элемент (кнопка) или точка на экране. Точка нужна контекстному меню на этапе 7, её поддержка делается сейчас.
- Коридор для диагонального движения мыши к подменю, поиск по первым буквам, переход по кругу — по каталогу.

### Select

- Обобщённый по типу значения, тип выводится из вариантов, как у ToggleButtonGroup.
- Варианты с иконками, отключённые варианты, разделители. Необязательное действие внизу списка.
- Список открывается так, чтобы выбранный вариант был виден.
- На закрытом поле стрелки не меняют значение — по каталогу.
- Поиска внутри списка нет: это SearchableMenu на этапе 13.

### Popover

- Произвольное содержимое у элемента-якоря.
- Закрывается по Esc, клику снаружи и потере фокуса, как в каталоге.

### Dialog

- Управляемый: открытие и закрытие задаёт владелец.
- Заголовок обязателен, он же подпись диалога для экранного диктора. Необязательное описание. Кнопки внизу передаёт владелец.
- Затемнение фона — новый цветовой токен в обеих темах. Добавь его в список ожидаемых токенов теста тем, на страницу Colors и в таблицу палитры этапа 1. Это не текст, в проверку контраста он не входит.
- Проп `type` у Button: в диалогах нужна кнопка отправки формы. Пункт бэклога закрывается.
- ConfirmDialog, который вызывается из кода и возвращает ответ, — этап 7. Сейчас только примитив.

## Что не входит в этап

- MenuBar, ContextMenu, ConfirmDialog и связь меню с реестром команд: этап 7.
- SplitButton, FlagsField, SearchableMenu: этапы next.
- Перетаскивание всплывающих элементов.

## Критерии приёмки

- Все пять элементов есть, у каждого тесты и страница в разделе Components.
- Клавиатура и закрытие у каждого элемента соответствуют каталогу, фокус возвращается после закрытия.
- Всплывающие элементы не обрезаются родителями и правильно позиционируются у краёв экрана: переворачиваются и сдвигаются. Проверяю я на витрине.
- Всплывающие элементы внутри Dialog оказываются поверх диалога.
- У IconButton и обрезанного Label подсказки через Tooltip, атрибута `title` для этого больше нет.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят без ошибок и предупреждений.
