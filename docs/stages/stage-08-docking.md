# Этап 8. Докинг, окна и демо-сцена

Прочитай `CLAUDE.md` в корне репозитория и в `docs/ui-catalog.md` записи DockLayout и WindowTabMenu, разделы «Общие механизмы» (управление фокусом, горячие клавиши) и «Принятые решения». Все правила `CLAUDE.md` действуют на этом этапе. При противоречии главнее `CLAUDE.md`.

## Контекст

Сейчас редактор — это рамка: меню и тулбар сверху, строка состояния снизу, пустая рабочая область между ними. Этот этап превращает рабочую область в рабочее пространство редактора: окна во вкладках, перетаскивание, разделители, разворачивание окна, сохранение раскладки.

Окна, как и команды на этапе 7, добавляет интеграция через реестр. Каркас не содержит окон конкретного движка.

Кроме механизма, на этом этапе появляется **демо-сцена**: отдельная страница `demo.html`, доступная только в `pnpm dev`, как витрина. Это демонстрационная интеграция, которая собирает все точки расширения каркаса вместе и выглядит как редактор в стиле Unity. Она служит образцом для разработчиков движков и проверкой, что механизмы работают вместе, а не только поодиночке.

## Решения, принятые заранее

- **Демо-интеграция живёт в `src/demo/`, а не в `src/engine/`.** Папка `src/engine/` остаётся местом для настоящей интеграции движка, которую создаёт разработчик движка. Демо — образец рядом с ней.
- **`demo.html` — отдельная точка входа** со своим `main.tsx` в `src/demo/`. Доступна только в `pnpm dev` и не входит в сборку, как витрина. `index.html` остаётся редактором без интеграции.
- **Кто вызывает установку интеграции в `index.html`** — по-прежнему открытый вопрос бэклога, его решаем, когда появится настоящий движок. Демо-сцена этот вопрос не решает, у неё своя точка входа.
- **Код каркаса не импортирует ни `src/engine/`, ни `src/demo/`.** Это закрепляется правилом линтера.
- **Меню Window:** каркас даёт готовую функцию, которая по реестру окон регистрирует пункты «открыть окно» в указанном меню. Вызывает её интеграция, где и как захочет. Сам каркас меню Window не создаёт.
- **Раскладка по умолчанию задаётся интеграцией.** В демо — классическая раскладка Unity: Hierarchy слева, по центру Scene и Game вкладками, Inspector справа, Project снизу.

## Разрешённые зависимости

- `dockview-react`, последняя стабильная версия, точная. Только бесплатный пакет, `dockview-enterprise` запрещён.

## Требования

### Реестр окон

- Тип окна: идентификатор, заголовок `MessageRef`, необязательная иконка, компонент содержимого, может ли окно существовать в нескольких экземплярах.
- Окно регистрирует интеграция при старте, как команды. Регистрация возвращает функцию отмены.
- Окно — обычный компонент. Внутри он пользуется всеми механизмами каркаса: регистрирует свои команды на время жизни через `useRegistration`, получает свою область горячих клавиш.
- Каждое окно автоматически становится областью горячих клавиш со своим идентификатором типа. Активное окно — то, в котором фокус. Клик по пустому месту окна переводит фокус в окно.
- Заголовки вкладок меняются при смене языка без перезагрузки.
- API: открыть окно по типу (если оно одиночное и уже открыто — активировать его), закрыть, проверить, открыто ли. Функция для меню Window построена на этом API.

### Докинг

- `dockview-react` оформлен токенами каркаса: фоны, вкладки, разделители, рамки, шрифт, размеры (`--size-tab-height`). Пункт бэклога про темизацию dockview закрывается. Переключение темы меняет вид докинга мгновенно.
- Вкладки перетаскиваются между группами, группы делятся перетаскиванием к краю, разделители тянутся мышью.
- Разворачивание окна на всю рабочую область и возврат.
- Плавающие окна и вынос окна в отдельное окно браузера на этом этапе выключены: это FloatingWindow из этапа next.
- Перетаскивание вкладок в dockview работает через HTML5 Drag and Drop. Проверь, что оно не конфликтует с роуминговым фокусом, всплывающими элементами и подавлением родного контекстного меню.

### Раскладка

- Раскладка сохраняется между сессиями и восстанавливается при загрузке.
- Сброс раскладки к раскладке по умолчанию — команда каркаса, которую интеграция может поставить в меню. Перед сбросом — ConfirmDialog.
- Сохранённая раскладка может ссылаться на тип окна, которого больше нет (интеграция обновилась). Такие окна при восстановлении пропускаются, остальная раскладка восстанавливается. Если сохранённая раскладка повреждена или несовместима, применяется раскладка по умолчанию, а приложение не падает.
- Хранилище раскладки устроено по образцу хранилища настроек темы и языка, с той же защитой от ошибок хранилища. Ключ хранилища предложи в 7.1 — то есть в 8.1. Выбор, обобщать ли `settingStorage` на значения JSON, тоже предложи в 8.1.
- Именованные раскладки — не на этом этапе, но формат хранения не должен их исключать.

### Меню вкладки

WindowTabMenu по каталогу: кнопка меню в заголовке группы и правый клик по вкладке. Пункты каркаса: развернуть или вернуть, закрыть вкладку, добавить вкладку (перечисляет окна из реестра). Окно добавляет свои пункты. Как окно добавляет пункты — через реестр контекстных меню этапа 7 или иначе — предложи в 8.1.

### Горячие клавиши, отложенные на этот этап

Решения из бэклога и каталога, отложенные до появления докинга:

- сочетание для разворачивания окна (кандидат в каталоге — Shift+Space);
- сочетания для переключения вкладок группы (кандидаты в каталоге — Alt+PageUp и Alt+PageDown);
- F6 для переключения областей: меню, тулбар, окна, строка состояния.

Проверь кандидатов на конфликты со списком сочетаний, которые забирает браузер, и с поведением полей ввода. Предложи решение в 8.1, зарегистрируй сочетания как команды каркаса в 8.4.

### Демо-сцена

- `demo.html` и `src/demo/main.tsx`: точка входа по образцу `src/app/main.tsx`, плюс установка демо-интеграции.
- Демо-интеграция в `src/demo/`, написанная так, как её написал бы разработчик движка, с поясняющей страницей на витрине:
  - окна Scene, Game, Hierarchy, Inspector, Project. Содержимое — простые заглушки с текстом через словарь демо-интеграции. Настоящих деревьев и полей ещё нет: они появятся на этапах 9 и 10, тогда заглушки заменятся;
  - меню File, Edit, GameObject, Window с несколькими командами. В Window — пункты из функции каркаса и сброс раскладки;
  - на тулбаре по центру Play, Pause, Step (переключатели с состоянием), слева несколько инструментов;
  - элемент в строке состояния;
  - раскладка по умолчанию — классическая раскладка Unity;
  - пара команд с сочетаниями клавиш и контекстным меню в Hierarchy.
- Демо не регистрирует окна консоли: консоль отложена отдельным пунктом бэклога.

### Витрина

- Страницы механизмов: Docking (реестр окон, открытие и закрытие, разворачивание), Layout (сохранение и сброс), Window tab menu.
- Примеры создают изолированные реестры и небольшой докинг с двумя-тремя тестовыми окнами.
- Страница Demo scene: как устроена демо-интеграция, ссылка на `demo.html`, ключевые фрагменты кода. Код показывается так же, как в примерах, из настоящих файлов `src/demo/`.

## Что не входит в этап

- Плавающие окна и вынос окна в отдельное окно браузера: этап next.
- Именованные раскладки.
- Настоящее содержимое окон демо: деревья, поля, вывод картинки движка.
- Окно консоли.
- Подключение интеграции в `index.html`.

## Критерии приёмки

- Интеграция регистрирует окно, не правя файлы каркаса; окно открывается, закрывается, перетаскивается, разворачивается.
- Докинг оформлен токенами и мгновенно меняется при смене темы.
- Раскладка сохраняется и восстанавливается; неизвестные окна пропускаются; повреждённая раскладка не роняет приложение.
- Сочетание, зарегистрированное окном в своей области, работает только когда фокус в этом окне.
- `demo.html` в `pnpm dev` показывает редактор в раскладке Unity с наполненными меню, тулбаром и строкой состояния; в сборку не попадает.
- `index.html` по-прежнему показывает каркас без интеграции.
- Код каркаса не импортирует `src/engine/` и `src/demo/`, это проверяет линтер.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят без ошибок и предупреждений, полный прогон после последней правки.
