# Этап 0. Каркас проекта

Прочитай `CLAUDE.md` в корне репозитория. Все его правила действуют на этом этапе.

## Цель

Получить пустой, но полностью настроенный проект: он собирается, запускается, проходит проверку типов, линтер и тесты. На экране пока ничего нет, кроме пустой страницы.

## Особенность этого этапа

Конфигурационные файлы тесно связаны между собой, поэтому этап разбит на подшаги. Каждый подшаг — одна небольшая группа файлов. После каждого подшага остановись, перечисли созданные файлы, кратко опиши решения и жди подтверждения.

## Разрешённые зависимости

Только эти пакеты. Всё остальное — через согласование.

- Рабочие: `react`, `react-dom`
- Разработка: `typescript`, `vite`, `@vitejs/plugin-react`, `@types/react`, `@types/react-dom`, `eslint`, `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `prettier`, `vitest`

Версии последние стабильные. Zustand, dockview и прочее на этом этапе не ставятся.

## Подшаги

### 0.1. Инициализация

- Проект на pnpm, Vite, React, TypeScript.
- Можно использовать шаблон `pnpm create vite` с шаблоном `react-ts`, но затем удалить весь демонстрационный контент: логотипы, демо-стили, счётчик, ассеты, комментарии.
- `.gitignore` для Node и Vite.
- В `package.json` скрипты: `dev`, `build`, `preview`, `typecheck`, `lint`, `format`, `test`.

### 0.2. TypeScript

- Режим `strict` плюс `noUncheckedIndexedAccess`, `noImplicitOverride`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`, `exactOptionalPropertyTypes`.
- Алиас `@/` указывает на `src/` и настроен одинаково в TypeScript, Vite и Vitest.
- Скрипт `typecheck` проверяет типы без сборки.

### 0.3. Линтер и форматтер

ESLint в формате flat config. Правила должны автоматически ловить нарушения `CLAUDE.md`:

- ошибка на `any`
- ошибка на non-null assertion
- ошибка на `@ts-ignore`; `@ts-expect-error` допускается только с описанием
- ошибка на `export default` в `src/`; конфигурационные файлы в корне — исключение
- правила `react-hooks` и `react-refresh`

Prettier с минимальной конфигурацией, не конфликтующий с ESLint.

Отдельно: правило «никаких комментариев» тоже нужно проверять автоматически. Предложи способ (правило ESLint, плагин или небольшой скрипт проверки `src/`), объясни плюсы и минусы и жди моего решения. Не добавляй ничего без согласования.

### 0.4. Тесты

- Vitest настроен и использует тот же алиас `@/`.
- Скрипт `test` проходит успешно, даже когда тестов ещё нет.

### 0.5. Точка входа

- `index.html` с корректным `lang`, `viewport` и заголовком «Editor».
- `src/app/main.tsx`: монтирует корневой компонент в строгом режиме React.
- `src/app/App.tsx`: корневой компонент, который пока рендерит пустой контейнер на весь экран.
- Без стилей, кроме сброса отступов у `html` и `body` и высоты на весь экран. Темы и токены появятся на этапе 1.
- Пустые папки из структуры в `CLAUDE.md` не создавай, они появятся вместе с файлами.

## Что не входит в этап

- Темы, токены, цвета
- Любые UI-компоненты
- Zustand, dockview, иконки
- Роутинг

## Критерии приёмки

- `pnpm dev` открывает пустую страницу без ошибок и предупреждений в консоли браузера.
- `pnpm build` проходит.
- `pnpm typecheck`, `pnpm lint`, `pnpm test` проходят без ошибок и предупреждений.
- В `src/` нет ни одного комментария и ни одного `export default`.
- В репозитории не осталось файлов из демо-шаблона Vite.
