# Бэклог

Отложенные задачи и известные ограничения. Пункт добавляется в том же шаге, где его обнаружили, и удаляется, когда сделан.

Формат пункта: что сделать, почему отложено, когда вернуться.

## Отложено осознанно

### Новая цветовая палитра

- **Что:** переделать цветовую палитру обеих тем. Текущая серая схема не нравится.
- **Почему отложено:** этап 1 закладывал механизм токенов и тем, а не финальный облик.
- **Когда вернуться:** отдельной задачей, до того как появится много окон. Тест контраста `src/themes/themes.test.ts` страхует от нечитаемых сочетаний. У светлых статусов и `border-focus` на `bg-header` запас над порогом всего 0.10, поэтому любая правка фонов светлой темы потребует пересчитать эти цвета.

### Переход на TypeScript 7

- **Что:** обновить TypeScript до версии 7.
- **Почему отложено:** typescript-eslint её пока не поддерживает.
- **Когда вернуться:** когда в typescript-eslint появится поддержка TypeScript 7.

### Состояние «нажато» у акцентной кнопки

- **Что:** задать цвет нажатой акцентной кнопки, темнее `accent-hover`.
- **Почему отложено:** кнопок ещё нет. `accent-hover` уже темнее `accent` ради контраста белого текста, поэтому «нажато» должно быть ещё темнее. Белый текст на нём проходит AA автоматически.
- **Когда вернуться:** на этапе UI-примитивов.

### Темизация dockview

- **Что:** переопределить стили dockview через токены, чтобы докинг выглядел частью редактора.
- **Почему отложено:** докинга ещё нет.
- **Когда вернуться:** на этапе докинга.

### Переключатель темы на витрине

- **Что:** перевести `src/showcase/ThemeSwitcher.tsx` с нативных радиокнопок на собственные UI-примитивы.
- **Почему отложено:** UI-примитивов ещё нет.
- **Когда вернуться:** на этапе UI-примитивов, когда появится аналог переключателя или группы кнопок.

### Кнопки витрины на UI-примитивах

- **Что:** перевести кнопку копирования кода `src/showcase/template/CopyButton.tsx` и кнопки в примерах витрины с нативных `<button>` на собственные UI-примитивы.
- **Почему отложено:** UI-примитивов ещё нет.
- **Когда вернуться:** на этапе UI-примитивов, когда появится кнопка.

### Синхронизация темы между вкладками

- **Что:** при смене темы в одной вкладке менять её и в других, через событие `storage`.
- **Почему отложено:** инструкция этапа этого не требовала, при обсуждении 1.5 решили не делать.
- **Когда вернуться:** если редактор и витрина будут часто открыты одновременно и расхождение начнёт мешать.

### Отключение анимаций при смене темы

- **Что:** на время смены темы отключать не только `transition`, но и `animation`.
- **Почему отложено:** анимаций цветов пока нет, а инструкция говорила только о переходах.
- **Когда вернуться:** когда появится первая CSS-анимация, затрагивающая цвета.

## Известные ограничения

### Вспышка фона в `pnpm dev`

- **Что:** при загрузке в dev-режиме возможна короткая вспышка фона.
- **Почему отложено:** в dev стили подключаются через JS после разбора страницы. В `pnpm build` и `pnpm preview` вспышки нет, это проверено.
- **Когда вернуться:** не требуется, если ограничение не мешает разработке.

### Встроенный скрипт темы и CSP

- **Что:** встроенный скрипт в `index.html` и `showcase.html` потребует хэш или nonce, если ввести политику безопасности контента (CSP).
- **Почему отложено:** CSP сейчас нет.
- **Когда вернуться:** при введении CSP. При любом изменении логики выбора темы (например, при добавлении нового режима) скрипт нужно править в обоих HTML-файлах вместе с TS-кодом. Расхождение поймает `src/app/themeBootstrap.test.ts`.

### Полосы прокрутки в разных браузерах

- **Что:** в Chrome и Firefox полосы оформлены стандартными `scrollbar-width` и `scrollbar-color`. В Safari работает fallback через `::-webkit-scrollbar`. Скрываются ли стрелки в Chrome на Windows, не проверено.
- **Почему отложено:** нет машины с Windows.
- **Когда вернуться:** при первой проверке на Windows.

### Ограничения проверки контраста

- **Что:**
  - `parseHexColor` понимает только `#rrggbb`;
  - полупрозрачные токены не проверяются: `overlay-*`, `playmode-tint`, `shadow`;
  - `text-disabled` исключён из проверки;
  - нет пар для фонов, на которых текст появится позже: текст на `bg-control`, текст поверх `overlay-hover` и `overlay-active`, текст на `bg-app`;
  - рамка фокуса `border-focus` не проверяется на `accent`. В тёмной теме они одного оттенка, и рамка фокуса на акцентной кнопке может быть почти не видна.
- **Почему отложено:** этих сочетаний пока нет в интерфейсе.
- **Когда вернуться:** на этапе UI-примитивов, когда появятся кнопки и состояния наведения. Новые пары добавляются в `src/themes/contrastPairs.ts`.

### Псевдоним `@/` в CSS

- **Что:** псевдоним `@/` берётся из `tsconfig` (`resolve.tsconfigPaths`) и не работает в CSS `@import`.
- **Почему отложено:** сейчас CSS импортирует только файлы из своей папки через `./`, поэтому `global.css` и перенесён в `src/themes/`.
- **Когда вернуться:** если CSS понадобится импортировать файл из другой папки. Тогда добавить явный `resolve.alias` в `vite.config.ts`.

### Таблица палитры в документации сверяется вручную

- **Что:** таблица палитры в `docs/stages/stage-01-tokens-themes.md` справочная. С `dark.css` и `light.css` её никто автоматически не сверяет.
- **Почему отложено:** источник истины — файлы тем, а таблица нужна только для чтения.
- **Когда вернуться:** при переделке палитры. Либо обновить таблицу, либо заменить её ссылкой на витрину.

## Сделать, когда понадобится

### Подготовка к открытой публикации

- **Что:** лицензия, README, правила участия в разработке.
- **Почему отложено:** каркас ещё не готов к тому, чтобы им пользовались разработчики движков.
- **Когда вернуться:** перед первой публикацией репозитория.

### Название и оформление без Unity

- **Что:** не использовать название и графику Unity в названии и оформлении проекта. С Unity сходство только в раскладке и поведении.
- **Почему отложено:** у проекта пока нет публичного названия и оформления.
- **Когда вернуться:** при выборе названия, логотипа и иконки проекта, не позже подготовки к публикации.

### Запрет импортов из `src/engine/` в каркасе

- **Что:** ESLint-правило, запрещающее импорты из `src/engine/` в коде каркаса.
- **Почему отложено:** папки `src/engine/` ещё нет, правило пока записано только в `CLAUDE.md`.
- **Когда вернуться:** когда появится `src/engine/`. Нарушение должно ловиться линтером, а не ревью.

### Версия Node в `package.json`

- **Что:** добавить в `package.json` поле `engines` с поддерживаемой версией Node.
- **Почему отложено:** на этапе 0 проект собирался и запускался только локально, закреплять версию было не нужно.
- **Когда вернуться:** при настройке CI или когда над проектом начнут работать на других машинах.

### Скрипт `format:check`

- **Что:** добавить скрипт `format:check` (`prettier --check .`), который проверяет форматирование без перезаписи файлов. Сейчас есть только `format`, он перезаписывает файлы.
- **Почему отложено:** на этапе 0 хватало `format`, а проверку сейчас запускают вручную через `pnpm exec prettier --check .`.
- **Когда вернуться:** при настройке CI или когда проверку форматирования добавят в обязательный список «Проверка перед сдачей шага».

### Предупреждение о недоступном хранилище

- **Что:** если хранилище браузера недоступно, показывать в Console предупреждение, что настройки не сохраняются.
- **Почему отложено:** окна Console ещё нет. Сейчас адаптер `src/state/theme/themeStorage.ts` молча возвращает тему по умолчанию.
- **Когда вернуться:** когда появится окно Console. Адаптеру понадобится способ сообщить о недоступности хранилища.

### Общий тип `Unsubscribe`

- **Что:** вынести тип `Unsubscribe` из `src/state/theme/systemTheme.ts` в общий модуль.
- **Почему отложено:** сейчас он используется только в коде темы.
- **Когда вернуться:** когда тип понадобится второй раз вне `state/theme`.

### Тесты компонентов

- **Что:** подключить jsdom и Testing Library.
- **Почему отложено:** сейчас тестируется только логика в окружении `node`. Новые пакеты согласуются отдельно.
- **Когда вернуться:** когда понадобятся тесты компонентов. Тогда же можно покрыть тестами:
  - `src/state/theme/themeController.ts` — он обращается к `window`;
  - `src/showcase/contrastRows.ts`.

### Остановка стора темы

- **Что:** метод `dispose` у стора темы, снимающий подписку на тему ОС.
- **Почему отложено:** рабочий экземпляр живёт столько же, сколько страница.
- **Когда вернуться:** если стор начнут создавать и уничтожать во время работы, например при горячей замене модулей или в тестах компонентов.

### Защита от отсутствующего `matchMedia`

- **Что:** работать без `window.matchMedia`, считая, что ОС предпочитает тёмную тему.
- **Почему отложено:** `matchMedia` есть во всех целевых браузерах, при обсуждении 1.5 решили защиту не добавлять. Во встроенном скрипте вызов уже обёрнут в `try`.
- **Когда вернуться:** если редактор понадобится запускать в окружении без `matchMedia`.

### Чтение значений токенов вне витрины

- **Что:** `src/showcase/useTokenValues.ts` читает `getComputedStyle` при каждой перерисовке.
- **Почему отложено:** на витрине перерисовка бывает только при смене темы, это дёшево.
- **Когда вернуться:** если похожий хук понадобится в редакторе, где перерисовки частые. Тогда добавить кэширование по теме.
