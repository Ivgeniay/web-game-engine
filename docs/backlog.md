## Известные ограничения

### Атрибут `lang` до запуска JS

- **Что:** в `index.html` и `showcase.html` записан `lang="en"`. Если сохранён русский язык, атрибут остаётся `en`, пока не запустится модульный скрипт и `startLanguageController`.
- **Почему отложено:** визуально это незаметно, а установка языка во встроенном скрипте дублировала бы логику выбора языка ещё в двух HTML-файлах. Решено при обсуждении 3.1.
- **Когда вернуться:** если появится зависимость от `lang` до запуска JS: CSS по `:lang()`, переносы `hyphens: auto` в первом кадре, требования доступности.

### Защита от текстов в обход локализации

- **Что:** ESLint-правило ловит только текст прямо в JSX: `JSXText`, строку или шаблонную строку в `{}` среди дочерних элементов, литерал в атрибутах `alt`, `aria-*` с текстом, `label`, `placeholder`, `title`. Оно не ловит текст в константе (`const LABEL = 'Reset'`, затем `{LABEL}`), строки в данных и реестрах, `document.title`, конкатенацию и пропсы с другими именами.
- **Почему отложено:** по синтаксису линтер не может отличить текст для человека от технической строки. Основная защита — типы: подписи в реестрах имеют тип `MessageRef`. Остальное проверяется на ревью. Решено при обсуждении 3.1.
- **Когда вернуться:** если у UI-примитива появится текстовый проп с именем не из списка текстовых атрибутов правила в `eslint.config.js`: тогда добавить имя в список. Примитивы этапа 5 называют текстовые пропсы `label` или принимают строку в `children`, оба случая правило ловит, это проверяет `src/eslintConfig.test.ts`.

### Вспышка фона в `pnpm dev`

- **Что:** при загрузке в dev-режиме возможна короткая вспышка фона.
- **Почему отложено:** в dev стили подключаются через JS после разбора страницы. В `pnpm build` и `pnpm preview` вспышки нет, это проверено.
- **Когда вернуться:** не требуется, если ограничение не мешает разработке.

### Встроенный скрипт темы и CSP

- **Что:** встроенный скрипт в `index.html` и `showcase.html` потребует хэш или nonce, если ввести политику безопасности контента (CSP).
- **Почему отложено:** CSP сейчас нет.
- **Когда вернуться:** при введении CSP. При любом изменении логики выбора темы (например, при добавлении нового режима) скрипт нужно править в обоих HTML-файлах вместе с TS-кодом. Расхождение поймает `src/app/themeBootstrap.test.ts`.

### Полосы прокрутки в разных браузерах

- **Что:** в Chrome и Firefox полосы оформлены стандартными `scrollbar-width` и `scrollbar-color`. В Safari работает fallback через `::-webkit-scrollbar`. Скрываются ли стрелки в Chrome на Windows, не проверено.
- **Почему отложено:** нет машины с Windows.
- **Когда вернуться:** при первой проверке на Windows.

### Ограничения проверки контраста

- **Что:**
  - `parseHexColor` понимает только `#rrggbb`;
  - полупрозрачные токены не проверяются: `overlay-*`, `playmode-tint`, `shadow`;
  - `text-disabled` исключён из проверки;
  - нет пар для фонов, на которых текст появится позже: текст поверх `overlay-hover` и `overlay-active`, текст на `bg-app`.
- **Почему отложено:** этих сочетаний пока нет в интерфейсе.
- **Когда вернуться:** на этапе UI-примитивов, когда появятся кнопки и состояния наведения. Новые пары добавляются в `src/themes/contrastPairs.ts`.

### Рамка фокуса акцентной кнопки

- **Что:** у варианта `accent` рамка фокуса вынесена наружу с зазором 1px (`src/ui/button/buttonStyles.module.css`), потому что `border-focus` на `accent` почти не виден: 1.40 в тёмной теме и 1.20 в светлой. Вынесенная рамка лежит на фоне вокруг кнопки, и её контраст проверяется парами `border-focus` на поверхностях. Ограничения: на `bg-app` в светлой теме контраст рамки 2.48, ниже порога 3; родитель с `overflow: hidden` обрежет рамку.
- **Почему так:** акцентные кнопки стоят на панелях, в заголовках, полях и всплывающих окнах, а не на `bg-app`. Геометрию рамки тест контраста не проверяет.
- **Когда вернуться:** если акцентная кнопка окажется прямо на `bg-app` или в контейнере, который обрезает содержимое.

### Обе темы на странице иконок одновременно

- **Что:** показывать иконки на витрине в тёмной и светлой теме рядом, без переключения.
- **Почему не сделано:** тёмная тема задана на `:root` и `:root[data-theme='dark']`, поэтому вложенный блок с `data-theme` её не получает. Для показа рядом пришлось бы менять селекторы тем. Темы проверяются переключателем в шапке витрины.
- **Когда вернуться:** если селекторы тем будут меняться по другой причине.

### Тест конфигурации ESLint на существующих файлах

- **Что:** `src/eslintConfig.test.ts` проверяет фрагменты кода через `ESLint.lintText` с путями существующих файлов: правила с типами работают только для файлов, которые знает проект TypeScript. Если такой файл переименуют или удалят, тест упадёт с ошибкой разбора, а не с понятным сообщением.
- **Почему так:** добавлять отдельные файлы-образцы или `allowDefaultProject` ради теста сложнее, чем следить за пятью путями в одном месте.
- **Когда вернуться:** если пути в тесте придётся править чаще одного раза за этап.

### Отключённые элементы в тулбаре

- **Что:** отключённые кнопки выпадают из порядка Tab и стрелок, поэтому с клавиатуры нельзя узнать, что в тулбаре есть недоступная команда. WAI-ARIA допускает фокусируемые отключённые элементы тулбара через `aria-disabled`.
- **Почему отложено:** на этапе 5 решено использовать нативный `disabled` у всех примитивов.
- **Когда вернуться:** на этапе 7, когда кнопки тулбара свяжутся с командами и их доступность станет меняться по условию команды.

### Переполнение тулбара

- **Что:** прятать элементы, которые не помещаются в Toolbar, в меню «ещё». Сейчас они сжимаются или выходят за край.
- **Почему отложено:** в каталоге это `later`, и для меню нужен этап 6.
- **Когда вернуться:** когда появятся окна с длинными тулбарами, не раньше этапа 6.

### Диалог, открытый из всплывающего элемента

- **Что:** Dialog, открытый из Popover или Menu, окажется под ними: у диалога `--z-modal` (300), у Popover и Menu `--z-dropdown` (400). Порядок всплывающих элементов задают только токены их вида.
- **Почему отложено:** на этапе 6 такого случая нет. Внутри Dialog всплывающие элементы оказываются поверх него, как и нужно.
- **Когда вернуться:** когда диалог понадобится открывать из меню или Popover без их закрытия. Вероятно, на этапе 7 вместе с ConfirmDialog: тогда закрывать родительский элемент перед открытием диалога или поднимать z-index по глубине дерева.

### Подсказки при перетаскивании

- **Что:** не показывать Tooltip, пока идёт перетаскивание, как требует каталог.
- **Почему отложено:** механизма перетаскивания ещё нет.
- **Когда вернуться:** вместе с механизмом перетаскивания. Проще всего ставить на время перетаскивания атрибут `data-popup-blocks-tooltips`, как это делают открытые меню.

### Подсказки на отключённых элементах

- **Что:** у отключённой кнопки нет подсказки: нативный `disabled` не получает событий мыши.
- **Почему отложено:** на этапе 5 решено отключать примитивы нативным `disabled`.
- **Когда вернуться:** вместе с пунктом «Отключённые элементы в тулбаре»: переход на `aria-disabled` вернёт и подсказки.

### Пределы проверки геометрии иконок

- **Что:** `findIconGeometryProblems` проверяет координаты точек, половинные координаты прямых линий, крайние точки кругов, залитые детали и команды путей. Она не видит выступ острых стыков за рабочую область, крайние точки дуг `A` и наклон диагоналей.
- **Почему так:** эти случаи редки, а точный расчёт сложнее самой проверки. Острые стыки и дуги проверяются глазами в увеличенном виде витрины.
- **Когда вернуться:** если иконка с выступающим стыком или дугой пройдёт проверку и будет замечена на витрине.

### Псевдоним `@/` в CSS

- **Что:** псевдоним `@/` берётся из `tsconfig` (`resolve.tsconfigPaths`) и не работает в CSS `@import`.
- **Почему отложено:** сейчас CSS импортирует только файлы из своей папки через `./`, поэтому `global.css` и перенесён в `src/themes/`.
- **Когда вернуться:** если CSS понадобится импортировать файл из другой папки. Тогда добавить явный `resolve.alias` в `vite.config.ts`.

### Таблица палитры в документации сверяется вручную

- **Что:** таблица палитры в `docs/stages/stage-01-tokens-themes.md` справочная. С `dark.css` и `light.css` её никто автоматически не сверяет.
- **Почему отложено:** источник истины — файлы тем, а таблица нужна только для чтения.
- **Когда вернуться:** при переделке палитры. Либо обновить таблицу, либо заменить её ссылкой на витрину.

## Сделать, когда понадобится

### Подготовка к открытой публикации

- **Что:** лицензия, README, правила участия в разработке.
- **Почему отложено:** каркас ещё не готов к тому, чтобы им пользовались разработчики движков.
- **Когда вернуться:** перед первой публикацией репозитория.

### Название и оформление без Unity

- **Что:** не использовать название и графику Unity в названии и оформлении проекта. С Unity сходство только в раскладке и поведении.
- **Почему отложено:** у проекта пока нет публичного названия и оформления.
- **Когда вернуться:** при выборе названия, логотипа и иконки проекта, не позже подготовки к публикации.

### Запрет импортов из `src/engine/` в каркасе

- **Что:** ESLint-правило, запрещающее импорты из `src/engine/` в коде каркаса.
- **Почему отложено:** папки `src/engine/` ещё нет, правило пока записано только в `CLAUDE.md`.
- **Когда вернуться:** когда появится `src/engine/`. Нарушение должно ловиться линтером, а не ревью.

### Кто вызывает установку интеграции

- **Что:** решить, откуда вызывается `EditorExtension` интеграции. Код каркаса не импортирует `src/engine/`, а точка входа `src/app/main.tsx` — тоже каркас. Варианты: разрешить импорт `@/engine` единственному файлу `src/app/main.tsx` правилом линтера; или отдельная точка входа интеграции в `src/engine/`, которая запускает редактор через функцию каркаса.
- **Почему отложено:** папки `src/engine/` ещё нет, API регистрации от выбора не зависит. Решено при обсуждении 7.1.
- **Когда вернуться:** на этапе 8, вместе с пунктом «Запрет импортов из `src/engine/` в каркасе».

### Версия Node в `package.json`

- **Что:** добавить в `package.json` поле `engines` с поддерживаемой версией Node.
- **Почему отложено:** на этапе 0 проект собирался и запускался только локально, закреплять версию было не нужно.
- **Когда вернуться:** при настройке CI или когда над проектом начнут работать на других машинах.

### Скрипт `format:check`

- **Что:** добавить скрипт `format:check` (`prettier --check .`), который проверяет форматирование без перезаписи файлов. Сейчас есть только `format`, он перезаписывает файлы.
- **Почему отложено:** на этапе 0 хватало `format`, а проверку сейчас запускают вручную через `pnpm exec prettier --check .`.
- **Когда вернуться:** при настройке CI или когда проверку форматирования добавят в обязательный список «Проверка перед сдачей шага».

### Предупреждение о недоступном хранилище

- **Что:** если хранилище браузера недоступно, показывать в Console предупреждение, что настройки не сохраняются.
- **Почему отложено:** окна Console ещё нет. Сейчас адаптер `src/state/storage/settingStorage.ts` молча возвращает значение по умолчанию для любой настройки: темы и языка.
- **Когда вернуться:** когда появится окно Console. Адаптеру понадобится способ сообщить о недоступности хранилища.

### Экранирование фигурных скобок в переводах

- **Что:** способ записать в тексте перевода буквальные `{` и `}`. Сейчас любая пара фигурных скобок считается плейсхолдером.
- **Почему отложено:** таких текстов пока нет. Решено при обсуждении 3.1.
- **Когда вернуться:** когда понадобится показать фигурные скобки в тексте интерфейса.

### Тесты компонентов для существующего кода

- **Что:** покрыть тестами в окружении jsdom `src/state/theme/themeController.ts` (он обращается к `window`) и `src/showcase/tokens/contrastRows.ts`.
- **Почему отложено:** jsdom и Testing Library подключены на этапе 4 для `Icon`, а эти модули к этапу не относятся.
- **Когда вернуться:** при следующей правке этих модулей.

### Остановка стора темы

- **Что:** метод `dispose` у стора темы, снимающий подписку на тему ОС.
- **Почему отложено:** рабочий экземпляр живёт столько же, сколько страница.
- **Когда вернуться:** если стор начнут создавать и уничтожать во время работы, например при горячей замене модулей или в тестах компонентов.

### Защита от отсутствующего `matchMedia`

- **Что:** работать без `window.matchMedia`, считая, что ОС предпочитает тёмную тему.
- **Почему отложено:** `matchMedia` есть во всех целевых браузерах, при обсуждении 1.5 решили защиту не добавлять. Во встроенном скрипте вызов уже обёрнут в `try`.
- **Когда вернуться:** если редактор понадобится запускать в окружении без `matchMedia`.

### Чтение значений токенов вне витрины

- **Что:** `src/showcase/tokens/useTokenValues.ts` читает `getComputedStyle` при каждой перерисовке.
- **Почему отложено:** на витрине перерисовка бывает только при смене темы, это дёшево.
- **Когда вернуться:** если похожий хук понадобится в редакторе, где перерисовки частые. Тогда добавить кэширование по теме.

### Подсветка синтаксиса в коде примеров

- **Что:** подсвечивать синтаксис в блоках кода витрины.
- **Почему отложено:** этап 2 запрещал новые пакеты, код примеров показывается моноширинным шрифтом без подсветки.
- **Когда вернуться:** когда примеры станут длинными и их станет трудно читать. Пакет для подсветки согласуется отдельно.

### Таблица свойств компонента

- **Что:** на страницах витрины показывать таблицу свойств компонента: имя, тип, значение по умолчанию, описание.
- **Почему отложено:** на этапе 5 решено описывать свойства текстом на страницах витрины. Генераторы документации на этапе 2 были запрещены, а таблицу, которую пишут вручную, никто не сверяет с типами.
- **Когда вернуться:** когда появятся составные элементы с десятком свойств и больше (этап 10) и текстом их станет трудно читать. Способ генерации таблицы из типов согласуется отдельно.

### Страницы витрины для компонентов интеграции

- **Что:** документировать на витрине окна и компоненты интеграции из `src/engine/`.
- **Почему отложено:** витрина документирует каркас, а интеграции движка пока нет. Код каркаса, в том числе витрина, не импортирует `src/engine/`, поэтому нужен отдельный механизм подключения таких страниц.
- **Когда вернуться:** когда в `src/engine/` появятся первые окна демонстрационной интеграции.
