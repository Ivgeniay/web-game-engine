# Каталог UI-элементов каркаса

Каталог описывает, какие UI-элементы нужны каркасу редактора, в каком порядке их делать и какие общие механизмы под них нужны. Unity — ориентир по набору элементов и поведению. Названия, иконки и тексты Unity в интерфейс каркаса не переносятся.

Окно консоли и журнала в каталог не входит: это комплексное, возможно интерактивное окно, его спроектируем отдельно позже.

## Источники

Документация Unity 6000.6, прочитана 2026-10-28:

- справочник элементов UI Toolkit: `docs.unity.com/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-element-ref`;
- IMGUI: `script-reference/unityeditor/editorgui`, `script-reference/unityeditor/editorguilayout`;
- оболочка: `EditorUtility.DisplayDialog`, `DisplayProgressBar`, `DisplayCancelableProgressBar`, `EditorWindow.ShowNotification`, `ShowAsDropDown`, `PopupWindow`, `GenericMenu`, `MenuItem`, `IMGUI.Controls.AdvancedDropdown`, страницы Overlays, Search window, Keyboard shortcuts, Inspector, Background Tasks window.

Заголовок компонента в инспекторе, окно выбора объекта и детали стыковки оверлеев в прочитанных страницах не описаны. Их описание в каталоге основано на общем знании редактора Unity и не сверено с документацией. Сведения о Godot и Unreal тоже даны по общему знанию.

## Как читать каталог

**Категории:**

- `primitive` — базовый элемент в `src/ui/`. Не знает о сторах и локализации, получает готовые строки через пропсы.
- `composite` — составной элемент из примитивов. Тоже не знает о сторах, если не сказано иное.
- `shell` — элемент оболочки каркаса: меню, тулбар, докинг, диалоги, уведомления. Знает о реестрах, командах и переводах.
- `engine-specific` — завязан на конкретный движок. В каркас не входит. Для каждого указан общий аналог и точка расширения.

**Приоритеты:** `MVP` — нужен для базового редактора, `next` — вскоре после, `later` — позже.

**Позиционирование** в зависимостях означает, что элементу нужен общий механизм всплывающих элементов на Floating UI (раздел «Общие механизмы»).

Общие для всех полей ввода правила, чтобы не повторять их в каждой записи:

- поле по возможности не даёт ввести недопустимое, а не сообщает об ошибке после;
- состояния: обычное, наведение, фокус (видимая рамка только при `:focus-visible`), отключено, только чтение, смешанное значение, значение некорректно;
- «значение некорректно» — для того, что фильтром ввода не отсечь: значение вне диапазона, пустое обязательное поле, незаконченный ввод вроде одного минуса. Рамка статусным цветом ошибки, сообщение в подсказке или под полем, `aria-invalid` и `aria-describedby`. Некорректное значение не фиксируется: по Enter и потере фокуса поле возвращает последнее корректное значение или приводит его к ближайшему допустимому для диапазона. Какой из двух вариантов — выбрать на этапе полей ввода;
- смешанное значение (несколько выбранных объектов с разными значениями) показывается прочерком, как в Unity, и не ломает ввод: новое значение применяется ко всем;
- изменение значения идёт по протоколу «предпросмотр / фиксация / отмена» (раздел «Отмена и повтор изменений значения»);
- подпись поля даёт `PropertyRow`, а не само поле.

## Primitive

### Icon

- **Аналог в Unity:** `Image` с иконкой редактора.
- **Назначение:** показать иконку из реестра по имени.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** реестр иконок. Делается на этапе «Иконки».
- **Клавиатура и фокус:** не фокусируется. Декоративная по умолчанию (`aria-hidden`), подпись — только у кнопки, которая её содержит.
- **Особенности:** красится через `currentColor`, размеры `--size-icon-sm` и `--size-icon-md`. Неизвестное имя — ошибка типов; для имён из данных интеграции нужна иконка-заглушка.

### Button

- **Аналог в Unity:** `Button`, `ToolbarButton`.
- **Назначение:** запустить действие.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Icon (необязательно, иконка слева от текста).
- **Клавиатура и фокус:** Enter и Space нажимают. Входит в обычный порядок Tab, внутри Toolbar — в роуминговый фокус.
- **Особенности:** варианты: обычная, акцентная, плоская для тулбаров. Размеры по `--size-control-height-*`. Нужно состояние «нажато» у акцентной кнопки (пункт бэклога).

### IconButton

- **Аналог в Unity:** `ToolbarButton` с иконкой, кнопки в заголовках окон и компонентов.
- **Назначение:** кнопка только с иконкой.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Icon, Tooltip.
- **Клавиатура и фокус:** как у Button.
- **Особенности:** подпись обязательна по типам: она идёт в `aria-label` и в подсказку. Квадратная, размер по высоте элемента управления.

### ToggleButton

- **Аналог в Unity:** `ToolbarToggle`.
- **Назначение:** кнопка с двумя состояниями: включено и выключено.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Button, Icon, Tooltip.
- **Клавиатура и фокус:** Enter и Space переключают. `aria-pressed`.
- **Особенности:** включённое состояние видно без цвета текста: фоном или рамкой. Пример применения — кнопка запуска игры, видимость сетки.

### ToggleButtonGroup

- **Аналог в Unity:** `ToggleButtonGroup`, панель инструментов перемещения и поворота.
- **Назначение:** выбрать один вариант (или несколько) из набора кнопок.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** ToggleButton.
- **Клавиатура и фокус:** группа — одна остановка Tab, стрелки ходят по кнопкам, Space и Enter выбирают. В режиме одного варианта — роль `radiogroup`.
- **Особенности:** режимы «ровно один», «ноль или один», «несколько». Заменит радиокнопки темы и языка на витрине (пункт бэклога).

### Label

- **Аналог в Unity:** `Label`, `LabelField`, `SelectableLabel`.
- **Назначение:** показать текст.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** нет.
- **Клавиатура и фокус:** не фокусируется. С флагом выделения текст можно выделить мышью и скопировать.
- **Особенности:** обрезка с многоточием и полным текстом в подсказке, стили второстепенного и отключённого текста через токены `text-*`.

### Kbd

- **Аналог в Unity:** подпись сочетания клавиш в пункте меню.
- **Назначение:** показать сочетание клавиш.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** нет. Готовую строку сочетания под платформу формирует механизм горячих клавиш.
- **Клавиатура и фокус:** не фокусируется.
- **Особенности:** на macOS символы ⌘ ⇧ ⌥ ⌃, на остальных платформах `Ctrl+Shift+…`.

### Separator

- **Аналог в Unity:** `ToolbarSpacer`, `Space`, разделитель меню.
- **Назначение:** разделить группы элементов.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** нет.
- **Клавиатура и фокус:** не фокусируется, роль `separator`.
- **Особенности:** горизонтальный и вертикальный, а также гибкий промежуток, который распирает тулбар.

### Checkbox

- **Аналог в Unity:** `Toggle`, `ToggleLeft`.
- **Назначение:** включить или выключить логическое значение.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Icon (галочка, черта смешанного состояния).
- **Клавиатура и фокус:** Space переключает. Фокус в обычном порядке Tab.
- **Особенности:** смешанное состояние (`aria-checked="mixed"`). Подпись слева через PropertyRow или справа своим пропсом, как `ToggleLeft`. Клик по подписи переключает.

### TextField

- **Аналог в Unity:** `TextField`, `DelayedTextField`, `PasswordField`.
- **Назначение:** ввести одну строку текста.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** нет.
- **Клавиатура и фокус:** Enter фиксирует, Esc возвращает значение на момент входа в поле и снимает фокус, Tab фиксирует и переходит дальше. Ctrl+Z внутри поля — родная отмена браузера до фиксации.
- **Особенности:** режимы фиксации: при каждом вводе или только по Enter и потере фокуса (аналог `Delayed*`). Тип «пароль» — пропсом, а не отдельным элементом. Горячие клавиши редактора не срабатывают, пока фокус в поле, кроме явно разрешённых.

### SearchField

- **Аналог в Unity:** `ToolbarSearchField`, `ToolbarPopupSearchField`.
- **Назначение:** фильтровать содержимое окна строкой поиска.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** TextField, IconButton, Icon (лупа, очистка).
- **Клавиатура и фокус:** Esc очищает, повторный Esc снимает фокус. Стрелка вниз переводит фокус в результаты (ListView, TreeView). Ctrl+F окна фокусирует поле — через горячие клавиши, а не внутри элемента.
- **Особенности:** кнопка очистки появляется, когда поле не пусто. Фильтрация с задержкой — задача потребителя, поле отдаёт значение сразу.

### NumberField

- **Аналог в Unity:** `IntegerField`, `FloatField`, `DoubleField`, `LongField`, `UnsignedIntegerField`, `UnsignedLongField`, `Delayed*Field`.
- **Назначение:** ввести целое или дробное число.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** TextField, механизм перетаскивания.
- **Клавиатура и фокус:** как у TextField. Стрелки вверх и вниз меняют значение на шаг, с модификатором — на крупный или мелкий шаг.
- **Особенности:**
  - построено на TextField и ограничивает ввод по типу. Целое — только цифры и минус в начале. Дробное — цифры, минус в начале и один десятичный разделитель (точка или запятая). Недопустимый символ не вводится. Вставка из буфера с недопустимым текстом отклоняется целиком;
  - изменение перетаскиванием: зону перетаскивания даёт подпись в PropertyRow или подпись оси в VectorField, курсор меняется на двустороннюю стрелку. Во время перетаскивания идёт предпросмотр, отпускание фиксирует, отмена возвращает исходное значение (раздел «Перетаскивание»);
  - модификаторы во время перетаскивания: точнее и грубее. Конкретные клавиши выбираются на этапе полей ввода;
  - режимы целого и дробного числа, минимум и максимум, шаг, точность отображения;
  - числа показываются по языку интерфейса, ввод принимает и точку, и запятую;
  - вычисляемые выражения (`2*3`, `+=5`), как в Unity, — `next`. Выражения конфликтуют со строгим фильтром ввода, поэтому это отдельный режим поля, в котором фильтр допускает операторы. Решение о нём — на этапе полей ввода;
  - большие целые (`long`) — через `bigint` или строку, решить при проектировании.

### Select

- **Аналог в Unity:** `DropdownField`, `EnumField`, `Popup`, `EnumPopup`, `IntPopup`.
- **Назначение:** выбрать одно значение из списка.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Menu или собственный список, Icon (стрелка), позиционирование.
- **Клавиатура и фокус:** Enter, Space и Alt+стрелка вниз открывают. В открытом списке стрелки, Home, End, поиск по первым буквам, Enter выбирает, Esc закрывает и возвращает фокус на поле. На закрытом поле стрелки не меняют значение, чтобы не менять его случайно при прокрутке клавиатурой.
- **Особенности:** список открывается так, чтобы выбранный пункт был виден. Пункты с иконками, отключённые пункты, разделители. Необязательное действие внизу списка («Добавить…») — нужно для аналога `TagField`.

### Foldout

- **Аналог в Unity:** `Foldout`.
- **Назначение:** свернуть и развернуть группу содержимого.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Icon (стрелка).
- **Клавиатура и фокус:** заголовок фокусируется, Enter и Space переключают, стрелка вправо разворачивает, влево сворачивает. `aria-expanded`.
- **Особенности:** Alt+клик разворачивает или сворачивает вложенные группы целиком, как в Unity. Состояние может быть управляемым, чтобы окно сохраняло его между сессиями.

### Tooltip

- **Аналог в Unity:** всплывающая подсказка `tooltip`.
- **Назначение:** показать короткое пояснение к элементу.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** позиционирование, слой всплывающих элементов.
- **Клавиатура и фокус:** показывается при наведении с задержкой и при фокусе с клавиатуры, Esc скрывает. Фокус не забирает, связь через `aria-describedby`.
- **Особенности:** после показа одной подсказки соседние показываются без задержки. Может содержать сочетание клавиш (Kbd). Не показывается, пока открыто меню или идёт перетаскивание.

### Menu

- **Аналог в Unity:** `GenericMenu`, `GenericDropdownMenu`, `ToolbarMenu`.
- **Назначение:** всплывающий список команд с подменю.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Icon (галочка, стрелка подменю), Kbd, Separator, позиционирование.
- **Клавиатура и фокус:** при открытии фокус на первом доступном пункте. Стрелки вверх и вниз по кругу, Home и End, вправо открывает подменю, влево и Esc закрывают текущий уровень. Enter и Space выполняют. Поиск по первым буквам. После закрытия фокус возвращается туда, откуда меню открыли.
- **Особенности:**
  - пункты: обычный, отключённый, с галочкой, переключатель-радио, подменю, разделитель, заголовок секции;
  - подменю открывается по наведению с задержкой и с «коридором» для диагонального движения мыши;
  - получает готовые строки и обработчики. Связь с реестром команд и переводами — в MenuBar и ContextMenu.

### Toolbar

- **Аналог в Unity:** `Toolbar`.
- **Назначение:** контейнер кнопок и полей вдоль края окна.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Button, IconButton, ToggleButton, Separator.
- **Клавиатура и фокус:** роуминговый фокус: весь тулбар — одна остановка Tab, стрелки влево и вправо ходят по элементам. Поля ввода внутри перехватывают стрелки себе.
- **Особенности:** высота `--size-toolbar-height`. Переполнение (элементы не помещаются) — `later`: прятать лишнее в меню «ещё».

### Dialog

- **Аналог в Unity:** модальное окно `EditorUtility.DisplayDialog`, утилитные окна.
- **Назначение:** модальное окно поверх редактора.
- **Категория:** primitive · **Приоритет:** MVP
- **Зависимости:** Button, IconButton, слой всплывающих элементов, механизм фокуса.
- **Клавиатура и фокус:** фокус заперт внутри, при открытии — на основном действии или первом поле. Esc отменяет, Enter выполняет основное действие, если фокус не в многострочном поле. После закрытия фокус возвращается на прежний элемент.
- **Особенности:** порядок кнопок по платформе не меняется, основное действие справа. Фон затемняется токеном. Открывается из кода через ConfirmDialog, а не разметкой в каждом месте.

### Link

- **Аналог в Unity:** `LinkButton`.
- **Назначение:** текст-ссылка, открывающий адрес или запускающий действие.
- **Категория:** primitive · **Приоритет:** next
- **Зависимости:** Icon (внешняя ссылка).
- **Клавиатура и фокус:** Enter активирует.
- **Особенности:** внешние адреса открываются в новой вкладке с иконкой внешней ссылки.

### Badge

- **Аналог в Unity:** счётчики сообщений в Console и строке состояния.
- **Назначение:** показать небольшое число или метку рядом с элементом.
- **Категория:** primitive · **Приоритет:** next
- **Зависимости:** Icon (необязательно).
- **Клавиатура и фокус:** не фокусируется.
- **Особенности:** статусный цвет — только у рамки или точки, текст токенами `text-*`. Большие числа сокращаются («999+»), строку формирует потребитель.

### RadioGroup

### Slider

- **Особенности:** поле ввода справа, как в Unity. Логарифмическая шкала — опция. Перетаскивание — предпросмотр, отпускание — фиксация. Godot показывает ползунок прямо внутри числового поля, когда диапазон известен; можно сделать вариантом NumberField.

## Composite

### PropertyRow

- **Аналог в Unity:** `PrefixLabel`, строка инспектора с подписью и полем.
- **Назначение:** строка «подпись — поле» с общим поведением инспектора.
- **Категория:** composite · **Приоритет:** MVP
- **Зависимости:** Label, Tooltip, любой элемент ввода, механизм перетаскивания, ContextMenu через пропсы.
- **Клавиатура и фокус:** клик по подписи фокусирует поле. Подпись не отдельная остановка Tab.
- **Особенности:**
  - для числовых полей подпись — зона перетаскивания (как в Unity);
  - ширина колонки подписей общая для окна и меняется перетаскиванием границы;
  - отступ по уровню вложенности;
  - правый клик по строке даёт меню свойства: копировать, вставить, сбросить. Пункты приходят через пропсы, PropertyRow сам меню не строит;
  - слот для отметки «значение изменено» слева от подписи (аналог отметок префаба) и для кнопки «сбросить» справа (как в Godot и Unreal, в Unity такой кнопки нет).

### VectorField

- **Аналог в Unity:** `Vector2Field`, `Vector3Field`, `Vector4Field`, `Vector*IntField`, `MultiFloatField`, `MultiIntField`.
- **Назначение:** несколько чисел в одной строке с подписями осей.
- **Категория:** composite · **Приоритет:** MVP
- **Зависимости:** NumberField, Label, механизм перетаскивания.
- **Клавиатура и фокус:** каждая компонента — своя остановка Tab, слева направо.
- **Особенности:** подписи осей (X, Y, Z, W или произвольные) — зоны перетаскивания для своей компоненты. Смешанное значение — у каждой компоненты отдельно. Цветные метки осей — токенами, если решим их вводить. Godot и Unreal позволяют связать пропорции компонент (замок у масштаба) — опция `next`.

### ListView

- **Аналог в Unity:** `ListView`.
- **Назначение:** список строк с выделением и прокруткой.
- **Категория:** composite · **Приоритет:** MVP
- **Зависимости:** виртуализация, механизм фокуса, Icon.
- **Клавиатура и фокус:** одна остановка Tab, активная строка через роуминговый фокус или `aria-activedescendant`. Стрелки, Home, End, PageUp, PageDown, поиск по первым буквам. Shift расширяет выделение, Ctrl (⌘) добавляет, Ctrl+A выделяет всё.
- **Особенности:** виртуализация для тысяч строк (длинные журналы, список файлов). Отрисовка строки — функцией потребителя. Перетаскивание строк — `next`.

### TreeView

- **Аналог в Unity:** `TreeView`, `MultiColumnTreeView`, окно иерархии.
- **Назначение:** дерево с разворачиванием, выделением и переименованием.
- **Категория:** composite · **Приоритет:** MVP
- **Зависимости:** ListView (виртуализация плоского списка видимых узлов), Icon, TextField (переименование), механизм перетаскивания.
- **Клавиатура и фокус:** как у ListView, плюс: вправо разворачивает или переходит к первому потомку, влево сворачивает или переходит к родителю, Alt+стрелка разворачивает и сворачивает поддерево, F2 (Enter на macOS) — переименование, Esc отменяет переименование.
- **Особенности:**
  - данные — плоская модель с идентификаторами, дерево не копируется в компонент;
  - перетаскивание с подсветкой места вставки: до, после, внутрь; автопрокрутка у краёв и автораскрытие узла при задержке над ним;
  - ленивая загрузка потомков;
  - фильтр по поиску показывает совпадения вместе с предками.

### ComponentHeader

- **Аналог в Unity:** `InspectorTitlebar`, заголовок компонента в инспекторе.
- **Назначение:** заголовок секции инспектора: свернуть, включить, имя, меню.
- **Категория:** composite · **Приоритет:** MVP
- **Зависимости:** Foldout, Checkbox, Icon, IconButton, Menu.
- **Клавиатура и фокус:** заголовок, флажок и кнопки — отдельные остановки Tab. Shift+F10 и клавиша контекстного меню открывают меню секции.
- **Особенности:** все части необязательны: иконка, флажок включения, кнопки справа (справка, меню). Правый клик по заголовку открывает то же меню. Перетаскивание заголовка для смены порядка секций — `later`. Содержимое меню даёт интеграция.

### ColorPicker

- **Зависимости:** SearchField, Badge, IconButton, Menu.
- **Клавиатура и фокус:** метки — роуминговый фокус, Delete и Backspace удаляют метку.
- **Особенности:** набор фильтров даёт окно-потребитель.

## Shell

### MenuBar

- **Аналог в Unity:** главное меню редактора.
- **Назначение:** главное меню из реестра пунктов.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** Menu, реестр меню, реестр команд, горячие клавиши, Kbd.
- **Клавиатура и фокус:** F10 (и Alt на Windows и Linux) переводит фокус в меню. Влево и вправо — соседние меню, вниз — открыть. Когда одно меню открыто, наведение на соседнее открывает его. Esc возвращает фокус в окно.
- **Особенности:**
  - пункты регистрируются по пути (как `MenuItem` в Unity: путь, порядок, разделители по разрыву порядка);
  - доступность и галочка пункта вычисляются при открытии из команды, как проверочный метод в Unity;
  - подписи — `MessageRef`, сочетания — из раскладки горячих клавиш;
  - заголовки секций в меню есть в Unreal, в Unity их нет.

### ContextMenu

- **Аналог в Unity:** `GenericMenu.ShowAsContext`, контекстные меню окон и полей.
- **Назначение:** меню по правому клику, собранное из реестра для текущего контекста.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** Menu, реестр меню, реестр команд, позиционирование от точки курсора.
- **Клавиатура и фокус:** Shift+F10 и клавиша контекстного меню открывают у элемента в фокусе. Дальше как у Menu.
- **Особенности:** контекст — идентификатор («дерево сцены», «вкладка окна», «свойство») плюс данные цели. Интеграция добавляет пункты в чужие контексты без правки каркаса. Родное меню браузера в редакторе подавляется, кроме полей ввода.

### MainToolbar

- **Аналог в Unity:** главный тулбар редактора.
- **Назначение:** верхний тулбар с кнопками из реестра.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** Toolbar, ToggleButton, ToggleButtonGroup, SplitButton (`next`), реестр тулбара, реестр команд.
- **Клавиатура и фокус:** как у Toolbar.
- **Особенности:** зоны: слева, по центру, справа. Порядок внутри зоны по приоритету. Состояние кнопок — из команд. Кнопки запуска, паузы и шага — пример демонстрационной интеграции, а не часть каркаса.

### StatusBar

- **Аналог в Unity:** строка состояния редактора.
- **Назначение:** нижняя строка с элементами из реестра.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** Label, Icon, IconButton, Badge (`next`), ProgressBar (`next`), Spinner (`next`), реестр строки состояния.
- **Клавиатура и фокус:** интерактивные элементы — обычные кнопки. Элемент реестра сам объявляет, нужно ли озвучивать его изменения (`role="status"`), чтобы чтец экрана не зачитывал всю строку подряд.
- **Особенности:** показывает только элементы из своего реестра, их содержимое даёт интеграция. Зоны слева и справа, порядок по приоритету. Высота `--size-statusbar-height`.

### DockLayout

- **Аналог в Unity:** докинг окон редактора.
- **Назначение:** раскладка окон с вкладками, разделителями и перетаскиванием.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** `dockview-react`, реестр окон, WindowTabMenu, ContextMenu.
- **Клавиатура и фокус:** сочетания для переключения вкладок группы и разворачивания окна на всю раскладку выбираются на этапе оболочки (этап 7) с учётом сочетаний, которые браузер не отдаёт. Кандидаты: Ctrl+Tab и Ctrl+Shift+Tab, Shift+пробел, как в Unity. Активное окно — то, где фокус; от него зависит контекст горячих клавиш.
- **Особенности:** сохранение, сброс и именованные раскладки. Темизация dockview через токены (пункт бэклога). Плавающие окна — FloatingWindow.

### WindowTabMenu

- **Аналог в Unity:** меню вкладки окна (кнопка «⋮» и правый клик по вкладке).
- **Назначение:** меню окна: развернуть, закрыть, добавить вкладку, пункты самого окна.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** IconButton, Menu, ContextMenu, реестр окон.
- **Клавиатура и фокус:** кнопка в заголовке группы — обычная остановка Tab. Дальше как у Menu.
- **Особенности:** окно добавляет свои пункты (например, «Закрепить» инспектора). Пункт «добавить вкладку» перечисляет окна из реестра.

### ConfirmDialog

- **Аналог в Unity:** `EditorUtility.DisplayDialog`, `EditorDialog`.
- **Назначение:** вызвать из кода диалог подтверждения и получить ответ.
- **Категория:** shell · **Приоритет:** MVP
- **Зависимости:** Dialog, Button, Checkbox («больше не спрашивать», `next`), стор диалогов.
- **Клавиатура и фокус:** как у Dialog. Фокус по умолчанию на безопасном действии для разрушительных операций.
- **Особенности:** вызов возвращает `Promise` с ответом. Тексты — `MessageRef`. «Больше не спрашивать» с ключом в хранилище, как в Unity, — `next`. Очередь: второй диалог ждёт закрытия первого.

### Notification

- **Аналог в Unity:** `EditorWindow.ShowNotification`. Всплывающие уведомления с кнопками и прогрессом есть в Unreal, в Unity их нет.
- **Назначение:** короткое сообщение, которое исчезает само.
- **Категория:** shell · **Приоритет:** next
- **Зависимости:** Icon, IconButton, Button, ProgressBar, стор уведомлений, слой `--z-notification`.
- **Клавиатура и фокус:** фокус не забирает, озвучивается через `aria-live`. Таймер останавливается при наведении и при фокусе внутри. Горячая клавиша переводит фокус к последнему уведомлению — `later`.
- **Особенности:** два места показа: поверх окна (как в Unity) и общий стек в углу редактора. Статус, необязательное действие, время показа — токен.

### CommandPalette

- **Аналог в Unity:** окно Search (Ctrl+K) частично. Палитра команд в чистом виде есть в Godot.
- **Назначение:** найти и выполнить любую команду по имени.
- **Категория:** shell · **Приоритет:** next
- **Зависимости:** Dialog или Popover, SearchField, ListView, Kbd, реестр команд.
- **Клавиатура и фокус:** горячая клавиша открывает, фокус в поиске, стрелки по результатам, Enter выполняет, Esc закрывает и возвращает фокус.
- **Особенности:** нечёткий поиск по переведённому имени и по английскому, последние команды наверху. Поставщики результатов от интеграции (объекты сцены, ассеты) — `later`.

### FloatingWindow

- **Аналог в Unity:** плавающие окна редактора, утилитные окна.
- **Назначение:** окно поверх раскладки, которое можно двигать и менять размер.
- **Категория:** shell · **Приоритет:** next
- **Зависимости:** DockLayout (плавающие группы dockview), механизм перетаскивания.
- **Клавиатура и фокус:** фокус не заперт. Esc не закрывает, закрытие — кнопкой или командой.
- **Особенности:** отдельные окна браузера (`window.open`, Document Picture-in-Picture) — `later`, отметить ограничения dockview.

### Overlay

- **Аналог в Unity:** оверлеи окна сцены.
- **Назначение:** плавающая панель или тулбар поверх содержимого окна, пристыковываемые к его краям.
- **Категория:** shell · **Приоритет:** next
- **Зависимости:** Toolbar, Popover, IconButton, механизм перетаскивания, реестр оверлеев.
- **Клавиатура и фокус:** оверлеи окна — отдельная группа остановок Tab после содержимого. Меню оверлеев открывается горячей клавишей окна (в Unity — обратный апостроф).
- **Особенности:** ориентация горизонтальная, вертикальная и панель; сворачивание в иконку; показ и скрытие из меню; положение сохраняется с раскладкой. Наборы положений (пресеты) — `later`. Реестр по типу окна, чтобы интеграция добавляла оверлеи в любое окно.

### SettingsWindow

- **Аналог в Unity:** окна Preferences и Project Settings.
- **Назначение:** окно настроек со списком разделов и поиском.
- **Категория:** shell · **Приоритет:** next
- **Зависимости:** SplitView, TreeView или ListView, SearchField, PropertyRow и поля, реестр разделов настроек.
- **Клавиатура и фокус:** список разделов и содержимое — две области, Tab переходит между ними.
- **Особенности:** каркас регистрирует разделы «Внешний вид» (тема, язык) и «Горячие клавиши». Интеграция добавляет свои разделы. Поиск подсвечивает совпадения в разделах.

### PickerDialog

- **Аналог в Unity:** окно выбора объекта (Object Picker).
- **Назначение:** выбрать элемент из большого набора с поиском, списком или сеткой.
- **Категория:** shell · **Приоритет:** next
- **Зависимости:** Dialog или FloatingWindow, SearchField, Tabs, ListView, GridView, Thumbnail.
- **Клавиатура и фокус:** фокус в поиске, стрелки по результатам, Enter выбирает и закрывает, Esc отменяет и возвращает исходное значение.
- **Особенности:** выбор на одинарный клик даёт предпросмотр в поле, как в Unity. Набор вкладок и поставщик элементов даёт потребитель. Это общий аналог Object Picker для ReferenceField.

### ProgressDialog

- **Аналог в Unity:** `EditorUtility.DisplayProgressBar`, `DisplayCancelableProgressBar`.
- **Назначение:** блокирующий прогресс долгой операции с отменой.
- **Категория:** shell · **Приоритет:** later
- **Зависимости:** Dialog, ProgressBar, Button.
- **Клавиатура и фокус:** фокус на «Отмена», Esc отменяет, если операция отменяемая.
- **Особенности:** вызов из кода, отмена через `AbortSignal`. В браузере блокировать интерфейс нужно реже, чем в Unity: по умолчанию предпочитать BackgroundTasks.

### ShortcutsWindow

- **Аналог в Unity:** окно Shortcuts Manager.
- **Назначение:** просмотр и переназначение горячих клавиш.
- **Категория:** shell · **Приоритет:** later
- **Зависимости:** TableView, SearchField, Kbd, Dialog, реестр команд, раскладка клавиш.
- **Клавиатура и фокус:** режим записи сочетания перехватывает следующую комбинацию, Esc выходит из записи.
- **Особенности:** показ конфликтов, сброс к умолчанию, профили — `later`.

### BackgroundTasks

- **Аналог в Unity:** окно Background Tasks и прогресс в строке состояния.
- **Назначение:** список фоновых задач с прогрессом, статусом и отменой.
- **Категория:** shell · **Приоритет:** later
- **Зависимости:** ListView, ProgressBar, Spinner, IconButton, StatusBar, стор задач.
- **Клавиатура и фокус:** как у ListView.
- **Особенности:** статусы: идёт, неопределённо, завершено, отменено, ошибка, нет отклика. Сводный прогресс в строке состояния, клик по нему открывает окно.

## Engine-specific

Эти элементы в каркас не входят. Для каждого указан общий аналог и точка расширения для движка.

### ObjectField

- **Аналог в Unity:** `ObjectField`.
- **Назначение:** ссылка на объект или ассет движка.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, `ReferenceField` (composite, `next`). Показывает иконку и имя цели, принимает перетаскивание, открывает PickerDialog, очищается.
- **Точка расширения:** поставщик ссылок: допустимые типы, имя и иконка по идентификатору, источник элементов для PickerDialog, проверка перетаскиваемых данных, переход к цели («показать в проекте»).
- **Клавиатура и фокус аналога:** Enter открывает PickerDialog, Delete очищает, Ctrl+C и Ctrl+V копируют ссылку.

### ObjectPicker

- **Аналог в Unity:** окно выбора объекта.
- **Назначение:** выбор объекта движка по типу.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, PickerDialog (раздел Shell).
- **Точка расширения:** поставщик элементов с поиском и вкладками (например, «Ассеты», «Сцена»).

### LayerField, LayerMaskField, RenderingLayerMaskField

- **Аналог в Unity:** одноимённые поля.
- **Назначение:** выбор слоя или маски слоёв движка.
- **Категория:** engine-specific
- **Аналог в каркасе:** отдельный элемент не нужен. Select и FlagsField с поставщиком вариантов.
- **Точка расширения:** поставщик вариантов (значение, подпись, отключён ли), необязательное действие «Изменить слои…».

### TagField

- **Аналог в Unity:** `TagField`.
- **Назначение:** выбор тега объекта.
- **Категория:** engine-specific
- **Аналог в каркасе:** отдельный элемент не нужен. Select с поставщиком вариантов и действием внизу списка.
- **Точка расширения:** поставщик вариантов и команда «добавить тег».

### PropertyField

- **Аналог в Unity:** `PropertyField`, `EditorGUILayout.PropertyField`. В Godot — плагины инспектора, в Unreal — настройка панели Details.
- **Назначение:** поле, выбранное по типу сериализованного свойства движка.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, механизм `PropertyEditor` (`next`): описание свойства в `contracts` (тип, имя, ограничения, только чтение) и реестр редакторов по типу в `core`. Каркас регистрирует редакторы для своих типов (число, строка, флажок, вектор, цвет, перечисление), интеграция — для своих.
- **Точка расширения:** описания свойств объекта, чтение и запись значений, свои редакторы для своих типов, атрибуты отображения (диапазон, многострочность, скрыть).

### InspectorElement

- **Аналог в Unity:** `InspectorElement`, пользовательские редакторы.
- **Назначение:** весь редактор выбранного объекта в инспекторе.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, механизм инспектора (`next`): по выделению собирает секции с ComponentHeader и PropertyEditor. Механизм живёт в каркасе, а само окно инспектора — в демонстрационной интеграции как образец для разработчиков движков.
- **Точка расширения:** источник выделения, разбиение объекта на секции, свой редактор для типа объекта целиком, меню секции.

### EditorToolbar, ToolContextToolbar

- **Аналог в Unity:** тулбары инструментов окна сцены.
- **Назначение:** инструменты движка: перемещение, поворот, масштаб.
- **Категория:** engine-specific
- **Аналог в каркасе:** отдельный элемент не нужен. MainToolbar или Overlay с ToggleButtonGroup и реестром.
- **Точка расширения:** регистрация инструментов, их иконок и горячих клавиш. Иконки инструментов регистрирует интеграция в своей папке.

### BuildTargetSelectionGrouping

- **Аналог в Unity:** вкладки платформ сборки.
- **Назначение:** настройки по платформам.
- **Категория:** engine-specific
- **Аналог в каркасе:** не нужен. Tabs с иконками.

### Предпросмотр ассета

- **Аналог в Unity:** `DrawPreviewTexture`, превью в инспекторе и окне проекта.
- **Назначение:** изображение ассета, построенное движком.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, Thumbnail (`later`) с поставщиком превью.
- **Точка расширения:** асинхронная функция превью по идентификатору с отменой и кэшем.

### Окно сцены

- **Аналог в Unity:** Scene view и Game view, gizmos и handles.
- **Назначение:** вывод картинки движка и работа с объектами в ней.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, `ViewportHost` (shell, `next`): контейнер холста с отслеживанием размера и плотности пикселей, фокусом для клавиатуры, захватом указателя, слотом для Overlay. Сама отрисовка, gizmos и handles — движок.
- **Точка расширения:** движок получает холст или элемент, размеры и события ввода, отдаёт состояние для оверлеев.

### Hash128Field, GUIDField

- **Аналог в Unity:** одноимённые поля.
- **Назначение:** показать идентификатор.
- **Категория:** engine-specific
- **Аналог в каркасе:** не нужен. TextField только для чтения и кнопка копирования.

### Отметки переопределений префаба

- **Аналог в Unity:** жирная подпись и полоса слева у изменённых свойств.
- **Назначение:** показать, что значение отличается от исходного.
- **Категория:** engine-specific
- **Аналог в каркасе:** да, слот отметки в PropertyRow (`next`).
- **Точка расширения:** состояние свойства (изменено, унаследовано) и пункты «вернуть», «применить» в меню свойства.

## Что не переносим из Unity

- `IMGUIContainer`, `TemplateContainer`, `VisualElement`, `BindableElement`, `Template`, `Instance`, `Columns` — механика UI Toolkit, у нас её делают React и CSS.
- `Box`, `Space`, `BeginHorizontal`, `BeginVertical`, `GetControlRect`, `ToolbarSpacer` — раскладка через CSS и Separator.
- `Delayed*Field`, `PasswordField`, `ToggleLeft`, `LogarithmicIntSlider`, беззнаковые и длинные числовые поля — опции TextField, Checkbox, Slider, NumberField, а не отдельные элементы.
- `BeginChangeCheck`, `BeginDisabledGroup`, `BeginProperty`, `BeginFadeGroup` — заменяются обработчиками изменения, атрибутом `disabled` у `fieldset`, протоколом изменения значения и CSS-анимацией.
- `DropShadowLabel`, `DrawRect`, `DrawTextureAlpha` — не нужны.

## Чего нет в Unity, но есть в других редакторах

| Что | Где есть | Как учтено |
|---|---|---|
| Палитра команд | Godot | CommandPalette, `next` |
| Кнопка «сбросить к умолчанию» у свойства | Godot, Unreal | слот в PropertyRow, `next` |
| Поиск по свойствам в инспекторе | Unreal (Details) | фильтр механизма инспектора, `later` |
| Числовое поле с полосой диапазона внутри | Godot (EditorSpinSlider) | вариант NumberField, `later` |
| Связанные пропорции компонент вектора | Godot, Unreal | опция VectorField, `next` |
| Всплывающие уведомления с кнопками и прогрессом | Unreal | Notification, `next` |
| Заголовки секций в меню | Unreal | пункт Menu, MVP |
| Редактор графов узлов | Unreal (Blueprint), Godot (визуальные шейдеры) | не в каталоге: отдельный крупный элемент, решить позже |

## Иконки для MVP и next

Только иконки каркаса. Иконки инструментов и сущностей движка (перемещение, поворот, камера, свет) регистрирует интеграция в `src/engine/` через тот же реестр. Нужны и для демонстрационной интеграции, но это её иконки.

| Иконка | Назначение | Приоритет |
|---|---|---|
| `close` | закрыть вкладку, диалог, уведомление; очистить поле | MVP |

## Общие механизмы

### Позиционирование всплывающих элементов

Решено: Floating UI.

- Один слой-портал для всплывающих элементов в корне приложения. Z-index только из токенов: `--z-dropdown`, `--z-tooltip`, `--z-modal`, `--z-notification`.
- Middleware: `offset`, `flip`, `shift`, `size` (ужать высоту списка под экран), `arrow` у Tooltip, если решим рисовать стрелку. `autoUpdate` при прокрутке и изменении размеров.
- Виртуальный якорь в точке курсора для ContextMenu.
- Вложенность: подменю и Popover внутри Popover. Клик в дочернем всплывающем элементе не закрывает родителя. Нужно дерево открытых всплывающих элементов.
- Закрытие по клику снаружи, Esc, потере фокуса, прокрутке якоря за пределы видимой области.
- Пакет: `@floating-ui/react`. Он нужен ради вложенных меню, коридора к подменю и управления фокусом.

### Управление фокусом

- Видимая рамка фокуса только при `:focus-visible`, токен `border-focus`. Проверка контраста рамки на `accent` — пункт бэклога.
- Роуминговый фокус для Toolbar, ToggleButtonGroup, RadioGroup, Tabs, Breadcrumbs: одна остановка Tab на группу.
- `aria-activedescendant` для списков, где фокус остаётся в поле поиска: SearchableMenu, CommandPalette, Select с поиском.
- Запирание фокуса в Dialog и возврат фокуса на прежний элемент после закрытия любого всплывающего элемента.
- Активное окно: окно, внутри которого фокус. От него зависят контекст горячих клавиш и пункты меню. Клик по пустому месту окна переводит фокус в окно.
- F6 (как во многих приложениях) переключает области: меню, тулбар, окна, строка состояния — предложение, решить при проектировании.

### Перетаскивание

Два разных механизма:

- **Изменение значения:** перетаскивание подписи числа, ползунки, разделители, ColorPicker. Pointer Events с `setPointerCapture`. Для бесконечного перетаскивания подписи числа — Pointer Lock API, как курсор Unity, который «проходит» через край экрана. Порог начала перетаскивания, чтобы клик не менял значение. Модификаторы точности.
- **Отмена перетаскивания значения:** без Pointer Lock — по `keydown` Esc. В режиме Pointer Lock браузер сам перехватывает Esc для выхода из захвата, и страница эту клавишу не получает. Поэтому там отмена срабатывает на выход из захвата (`pointerlockchange`), а не на `keydown` Esc.
- **Перенос данных:** строки дерева и списка, ссылки в ReferenceField, ассеты в окно сцены. Свой механизм на Pointer Events с типизированными данными переноса (тип плюс идентификаторы), подсветкой цели и правилами «можно ли бросить». HTML5 Drag and Drop только для файлов из ОС. Dockview использует HTML5 Drag and Drop для вкладок; проверить, что механизмы не конфликтуют.

### Горячие клавиши

- Реестр команд — источник истины: команда, подпись (`MessageRef`), сочетание по умолчанию, условие доступности, контекст.
- Контексты: глобальный, активное окно определённого типа, текстовое поле. Пока фокус в поле ввода, глобальные сочетания без модификаторов не срабатывают.
- `Mod` — Ctrl на Windows и Linux, ⌘ на macOS, как `%` в Unity. Сравнение по `KeyboardEvent.code` для букв, чтобы сочетания работали в русской раскладке.
- Браузер не отдаёт часть сочетаний: Ctrl+W, Ctrl+T, Ctrl+N, Ctrl+Tab в некоторых браузерах. Сочетания по умолчанию выбирать с учётом этого, список запрещённых проверять в тестах реестра.
- Строку для Kbd формирует механизм, а не компонент.
- Переназначение и хранение пользовательской раскладки — с ShortcutsWindow, `later`.

### Отмена и повтор изменений значения

- Протокол изменения значения у всех полей: `preview` (во время перетаскивания или ввода в режиме «при каждом вводе»), `commit` (отпускание, Enter, потеря фокуса), `cancel` (Esc: вернуть значение на начало изменения). Поле само отмену не хранит.
- Одно перетаскивание или одно редактирование — одна запись отмены, а не сотни. Запись создаётся на `commit` с начальным и конечным значением.
- Стек отмены живёт в `core` и работает с операциями, которые даёт интеграция через `contracts`: каркас не знает, как движок меняет данные. Группировка нескольких изменений в одну запись (изменение нескольких выбранных объектов, ListEditor).
- Ctrl+Z, пока фокус в текстовом поле с незафиксированным вводом, — родная отмена браузера. После фиксации — стек редактора.
- Окно истории отмены есть в Unity, Godot и Unreal — `later`.

### Виртуализация списков

Нужна ListView, TreeView, GridView, TableView и большим Select. Решается на этапе списков, предпочтительно свой модуль для строк фиксированной высоты.

## Принятые решения

- **Floating UI:** пакет `@floating-ui/react`. Нужны вложенные меню, коридор к подменю и управление фокусом.
- **Виртуализация списков:** решается на этапе 10, предпочтительно свой модуль для строк фиксированной высоты.
- **Модификаторы перетаскивания и выражения в NumberField:** решаются на этапе 9.
- **Некорректное значение при фиксации:** вернуть последнее корректное или привести к ближайшему допустимому — решается на этапе 9.
- **Окно инспектора:** механизм в каркасе, само окно — в демонстрационной интеграции как образец для разработчиков движков.
- **Сочетания для вкладок и разворачивания окна:** решаются на этапе 7.
- **Окно консоли и журнала:** в каталог не входит, проектируется отдельно позже.
